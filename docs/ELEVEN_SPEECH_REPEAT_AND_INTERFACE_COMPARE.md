# 十点半复读根因及9000/8807接口对比

## 根因与处理

截图里的“想看我的底牌？等亮牌再说。”是elevenSpeechFallback程序占位句。旧过滤器将任何与真实点数相等的数字都拦截，包括姓名中的九、惯用语中的一；还一概拦截“几张牌”这样的公开张数。每条被拦台词都换成同一句，前后端各执行一次；同一角色可有多个发言槽位，导致多条不同内容看起来成了复读。不是单凭截图就认定模型原样复读。

新聊天路径改用sanitizeElevenPublicLine：识别自我报点而非任意数字，正常称呼/口语/公开张数保留；真正的未公开真实点数片段、具体牌/花色和旁白仍不公开。危险片段被省略，安全余句保留；没有安全内容时该条静默，不编造替代台词。爆牌亮牌或结算后的公开信息可正常说。

同一手牌内同NPC逐字相同的长句（去空白至少8字）只保存一次；短行动用语、不同角色的相同短语与真实玩家输入不全局删除。新请求的publicLines也剔除旧占位与重复长句。所有NPC的hit/stand/null决定仍严格完整；删台词不删决定，不加模型调用，不重复发牌或喝酒。旧记录只在展示时隐藏已知占位和长句复读，不改写存档，不能复原当初已被替换掉的原话。

## 只读版本对比

核对基线：9000=test，源码5e5c3d9，运行快照25aa6be46c5e73e6；8807=stable，快照c0fb3b00676729bc。两者健康接口均报0.20.5及同一dataset，版本号相同不代表运行代码相同。对比只读提取了指定程序源码和健康信息，没有读取密钥或改服务配置。

- 底层请求结构均为model、messages、temperature、max_tokens、stream:true，以及配置启用的top_p/frequency_penalty/presence_penalty，使用所选连接地址与Bearer Key；两边页面的普通剧情均发送singleStateCall:true。
- 9000有party-game/eleven-batch/liar-dice及新十点半、大话骰任务；8807的冻结快照没有这些模块，也没有该底牌占位过滤器。不能拿两个端口对不同游戏任务的响应直接断言外部模型优劣。
- 旧国王react/game-interact主要使用固定replies及唯一角色约束；9000增加独立多句dialogue和公开历史处理。普通群聊本来就可多条，不是所有旧接口都一人一句。
- 9000已保留并脱敏显示实际上游HTTP及流内状态/原错误消息；8807仍为旧的分类提示方式。
- 上述是运行程序和请求构造方式的对比，不等于已验证用户两端当前选中相同的模型、API地址或采样参数。那些具体值来自各自页面配置，本次没有消耗用户真实模型做A/B调用。

验证：完整前端1000项、服务端525项通过，另5项跳过；补充旁白标记后再跑16项相关回归和生产构建通过。覆盖姓名/惯用语误伤、真假报点、公开张数、敏感片段保留余句、全部静默不丢决定、同手牌长句去重、旧记录展示不改档、固定请求次数和备份路径。

只发布9000修复；8807/8088不更新、不重启。AGENTS指定agent-hub路径在当前机器不存在，以本文及Git提交交接。
