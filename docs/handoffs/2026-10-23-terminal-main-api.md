## 最终调用策略

- 自动群聊、角色主动私聊、默认群初始化、主动好友申请及课表，随正文主 API 同一响应返回，不另调用终端模型。主请求带 `terminalContext`，唯一 `<SR_STATE>` 中增加 `terminal` 通讯伴随字段，最后仍按原协议 `<SR_DONE>` 结束。
- 初始化根据玩家身份和人际关系建立 2—5 个群，群主按创建者确定；每个正文轮，每个默认/剧情群返回 3—5 条成员消息。已有群的成员、名称、群主、管理员及公告固定；模型不得通过自动消息偷偷改权限或成员。
- 主动私聊可为空，只能由已经接受好友的角色发出；不替玩家回复。已生成的群聊与私聊进入终端原会话。
- 用户主动在私聊/群聊发言，才调用功能设置中选定的终端 API 生成回复。申请好友、游戏邀请、国王游戏及用户明确点击更新课表等动作也使用终端 API。国王游戏的角色反应有独立语义检查，不能承诺所有游戏操作只调用一次。
- 通讯 companion 单独校验，错误不丢弃正文或合法人物状态，也不自动追加模型修复调用；提示保留旧聊天，下一轮正文继续同步。变量生成关闭时仍可以传回通讯。
- 以轮次、选中版本和祖先内容绑定通讯与记忆，重复提交不重复追加。切换分支隐藏旧消息/记忆但保留历史。新批次同时写入正文下“小手机记忆”，终端内继续聊天更新同一轮记忆；摘要参与已有检索，最新终端摘要也注入正文请求。

## 个人终端功能

- 星空学院背景已生成并作为 WebP 放入 `public/assets/terminal-academy-night.webp`；底栏为桌面、通讯、好友、我的。时间跟随设备系统时间，剧情日期单独显示。
- 输入完整 11 位终端码查找单个角色，不展示全员名单、不支持姓名搜索通讯录。服务器按账号+存档+角色稳定生成码，密钥在忽略目录 `server/private/terminal-codes.key`；部署时保留该目录。正文索要号码时，模型按人设、关系和知情范围判断给不给，并使用真实码。
- 好友申请必须有理由，模型判断同意/拒绝；角色主动申请由用户接受/拒绝。未接受者不进入可邀游戏好友。
- 群资料、邀请、移除及管理员任免按群主/管理员权限校验，用户不是默认管理员。NPC 群主可在聊天回复中提出结构化管理动作，经程序校验后应用。
- 我的支持头像上传、缩放和位置调整，以及一句话简介；空简介为“这个家伙很懒，还没有写个人简介喵~”。人物头像暂为空白占位。
- 私聊与群聊历史完整保留，单页只渲染 20 条，可翻页、搜索。课表遵循学生/教官/其他教职工身份；明确剧情安排优先。
- 国王游戏实际调用终端 API，只邀请已接受好友。号码和国王由程序抽取。背叛命令必须由角色以本人身份拒绝并接受正常游戏惩罚，界面不再显示用户要求删除的系统拒绝说明。
- 不迁移或清理用户浏览器存档，不上传浏览器 API Key、部署密钥或服务器私有数据。
