# 来源记忆账本与三轮验收

实施日期：2026-10-19。基线：`66321c0fc94c14bbd27c6054d6f93bbd0262764c`。

依据用户提供的《记忆系统改造方案-shujuku.md》独立实现，未复制 shujuku 插件代码，也不需要酒馆宿主、SQL/WASM 或 iframe 脚本。

## 使用

1. 更新后进入 API 设置，点击“全部使用主 API · 本地记忆检索”。这会把文字任务统一到主 API，并关闭可选向量检索；已保存的副 API 和向量配置不会删除。
2. 记忆整理默认仍为累计 10 轮。未达到轮数只保存正文、状态和待处理任务，不额外调用文字模型。达到轮数后一次批量整理，使用主 API 时仍是一笔独立的记忆请求。
3. 在“剧情记忆”页面查看事件表、约定、来源、任务、修订与历史。可以编辑结构化事实和约定，也可以保留原有的记忆补充操作。
4. 新建的游戏存档使用来源账本。旧存档保留原检索；先点“查看迁移预览”，核对可映射和来源待确认的数量，再启用账本。迁移本身不调用模型或重建向量。

## 实现范围

- 继续用现有账号隔离的 IndexedDB 工作区。记录、来源、修订、任务和迁移原始快照随工作区备份保存，不切换数据库。
- 每条新事件保存 session/turn/variant、正文及输入指纹、状态指纹、修订号；任务使用相同来源产生稳定 ID。
- 候选检索验证所选回复、正文和前后状态。旧稿、改文、状态重修或回退导致来源失效时，旧事实不进入候选检索。
- 约定提出、履行和取消保存在对应轮次的事件记录内，按当前有效路径依次计算状态，后续履行不修改祖先记录。
- 回退移除的记忆进入历史归档；修订前的文字和结构化记录保存在修订历史。归档不进入当前路径召回。
- 先保存剧情，再运行独立后台队列。记忆整理期间可以继续发送剧情；迟到结果须重新验证来源和接口配置。记录与任务完成状态在同一工作区快照写入，写入失败回滚记录并保留失败任务。
- 手动重试只处理缺失、失败或来源发生变化的记录。自动后台任务不会在后续每轮重复调用同一失败批次。刷新前正在执行的任务标记中断，需显式重试；不自动重复付费调用。
- 新引擎提供本地 BM25（中文双字词）检索；有有效向量时用倒数排名融合。向量按模型、维度与文字匹配，编辑会使旧向量失效。向量不可用不撤销文字事实。
- 记忆提取继续只接收完整主线正文、行动、必要状态及已有约定。MVU 数字由前后状态计算，记忆模型不能写回人物状态；论坛、独立小剧场与私密 OS 不作为主线事实输入。
- 保留原引擎选项；切回时继续使用兼容格式的现有事件，不丢弃新引擎期间新增记录。原迁移快照和历史仍随备份保留。

来源指纹用于检测改文及状态改变，不是密码学签名。没有可靠来源的旧事件保留展示，不自动加入候选检索。迁移可重复执行，不重复建立原始快照或记录。

## 三轮真实模型测试

使用隔离测试存档及同一个主模型 `agnes-3.0-flash`。测试时把累计间隔临时设为 **2 轮**，向量关闭；产品默认 10 轮不变。使用本地最新代码和真实上游服务，系统 TLS 客户端仅作为测试环境的网络传输适配，未加入生产代码。

| 步骤 | 实测结果 |
|---|---|
| 第一轮询问参观条件并请求门牌对照表 | 正文完成，来源任务待累计，无记忆模型请求 |
| 第二轮确认领取并帮助整理资料 | 正文完成，创建一个两轮批量记忆请求，输入已恢复可用 |
| 上游限流 | 批量记忆及首次第三轮返回限流；前两轮正文完整保留，任务可见且可重试 |
| 手动重试记忆 | 原两条任务完成，生成两份有效结构化记忆；没有重演已完成正文 |
| 第三轮询问约定 | 请求携带 3 段召回内容，包含门牌对照表约定；正文正确回答“明日上午十点、学院接待处、值班接待员” |
| 累计规则 | 第三轮任务待累计，未擅自额外整理一轮 |
| 事实编辑与恢复 | 创建 v2 修订并保留 v1；恢复 v1 后成为 v3，刷新仍保留两次修订及来源 |
| 向量调用 | 0 次 |

按该测试设置，正常路径是三次剧情请求和一次批量记忆请求。实际因上游限流，多了一次用户主动重试剧情和一次主动重试批量记忆；没有自动重试循环。第三轮实际请求已核实包含召回约定，不能据此保证模型今后永远不遗忘或不虚构。

## 验证与边界

固定测试覆盖来源幂等、跨存档、切稿、正文/状态改变、约定履行后回退、迁移重复执行、旧数据保留、修订、备份恢复、后台不阻塞新剧情、保存失败可重试和可选向量。还扩大了记忆输入允许的动态 NPC 数量，使其与现有状态链的 1000 名上限一致。

没有引入额外重排模型，没有改世界书触发、美化或 MVU 数值写入逻辑。未使用额外 embedding 服务测试新引擎语义命中率，未做大规模性能基准；本次证实的是来源一致性、可恢复流程和上述三轮真实用例，不能宣称 BM25 在所有故事中优于原检索。
