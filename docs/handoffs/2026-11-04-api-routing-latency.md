# 8088 API 绑定与延迟排查

基于 3be8c93，用户确认反馈来自 8088，并表示不止一个功能。远程 main 仍 03cdd39，迁移分支开工前为 3be8c93；单写者 Codex。

## 修复与实际证据

- 原生 `readSecret` 在 id 缺失时会读取当前激活 Key。学院兼容层现在先要求显式临时凭据或明确存在于当前账号的 secret_id，缺失/失效/混用直接失败。URL、模型没有改用原生 UI 的默认值；临时头仍只允许 Authorization。
- 在首次等待之前复制任务 profile，以及原生预设推导时的 profile；终端配置在整个任务（包括唯一格式纠正和国王复核）内固定。
- 服务端原生调用提供目标 origin/模型标记；隐藏 SDK 引擎在交付成功回复之前核对该标记。不一致取消 body、抛出明确错误，不进行自动改接口重试。这里核对的是交给原版 handler 的目标，原版 handler 自己的后续重定向仍沿用原生行为，不能说成最终网络逐跳审计。
- 主窗口运行日志接收有限的阶段、origin、model 和 elapsedMs，区分原生准备与接口响应。没有 Key、票据、提示词、原始模型内容或新存档字段；日志继续排除在完整玩家下载、云端和恢复归档之外。
- 终端原来一次任务加载两遍整库，现在复用一个任务内的快照。NativePresets 读取世界书由串行改为每批最多四个并行，保持顺序、未知字段和绑定；并发读合并只在读请求进行时有效，后续读取仍取得新文件，返回值互不共享可变对象。没有永久预设缓存，避免切换后读旧配置。
- StoryContent 无显示正则时跳过不需要的结构扫描。保留原正文及 HTML/CSS 渲染，未发布改变段落结构或额外行内缓存的尝试。

## 验证

- 类型检查、学院与私有引擎构建通过。
- 最终前端全量 970 通过、3 既有跳过；后端 490 通过、4 既有跳过。
- 原版后端、私有编排及模拟上游 8 项完整请求链通过。
- 真实浏览器完整学院页面，故意将隐藏引擎原生全局地址/模型设置为另一接口，连接测试 A→B→A 仍收到准确地址、模型和 Key；随后真正保存主 API 到 A、再保存到 B，分别执行人设辅助，也准确到达对应模拟接口。所有 Key 均为合成值，共 12 次模拟请求、付费调用 0。
- 手机 390px、CPU 四倍减速、100 历史楼层及 70 次文本更新，实际 StoryView 10 个渲染楼层，无浏览器异常。样本有波动，未宣称获得可归因的渲染帧率提升。
- 生产临时账号写入合成的原生活跃 Key 后，未指定凭据的请求仍在任何外部转发前返回 MODEL_KEY_REQUIRED，证明没有使用该默认 Key。生产人设、好友、正文私有编排及账号票据检查通过，未发送真实作者资料到外部模型，未使用客户 Key。合成账号已清理。
- 未能复现用户原始“调用与设置不符”的具体一次请求；上述是独立确认并修复的风险。若继续反馈，直接查看新的运行日志阶段和接口记录，勿再次假定上游问题或清空用户 API 配置。

- 新版公开原生 PID1390885、私有原生 PID1390884、前端 PID1390886，均 active、NRestarts=0。
