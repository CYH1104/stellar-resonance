# 玩家身份与 API 白名单

主剧情原本已有完整玩家人设；此次补齐独立论坛评论请求，发送当前会话完整 persona 与当前关系参考。主剧情及论坛共用泛用身份规则，适用于校长、教师、学生、访客、校外职业、多重身份与未知身份，不默认玩家是新生、同校成员、下属或熟人。角色身份与既有关系按角色 ID 提供参考。

规则区分身份关系、认识程度、亲密关系和好感。参考明确人设与有时间依据的剧情变化，证据不足使用中性称呼；不从同校、岗位、年龄等擅自推断直属师生、同班、年级、熟悉程度或好感。论坛人物不能因系统知道秘密而自动知道秘密。同人内容不作为主线事实。本次不新增模型调用，不持久化新的推断关系表，也不保证模型百分百遵循提示词。

管理员登录 `/editor/` 后进入 `/editor/accounts` 的“允许使用的 API 地址与端口”，先读取白名单，再新增、删除和保存条目。条目为 origin，例如 `https://relay.example:8443` 或 `https://relay.example`，不包含 `/v1`、用户名、密钥、参数、片段。默认 HTTPS 端口为 443，HTTP 为 80；是否可使用 HTTP 仍受现有接口 URL 校验限制。

按协议、域名和端口精确匹配，不使用通配符。普通用户不能读写管理接口。服务器在配置接口及发出每个上游请求前校验，覆盖正文、补修、续写、摘要、人设、论坛、随机事件、向量、测试连接和查询模型。重定向被拒绝，不会自动转发密钥和提示词至另一个地址。移除条目后，已经保存的连接也不能继续发请求；不需要重启。

生产账号模式默认拒绝：白名单文件不存在或内容为空时全部禁止，读取异常时也不放行。升级后请管理员先加入允许的地址，不能从用户历史接口记录自动放行。无账号的 localhost 开发预览在没有配置任何条目时保留原调试行为；一旦添加条目，也按白名单执行。

配置保存在账号目录内 `relay-policy.json`（默认 `server/private/accounts/relay-policy.json`），不入库提交，不含密钥。服务器更新时保留该目录。地址数量最多 100 条。当前管理修改按整份列表保存，多管理员同时编辑前应先重新读取。
