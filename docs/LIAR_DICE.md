# 大话骰（斋／非）

## 本项目确认规则

- 玩家与已接受邀请的2～7位好友参加，每人每局5颗骰子。开局由程序独立摇出并保存，首局随机先叫；后续全员重新摇5颗，由上一局输家先叫，不扣骰。
- 起叫数量至少为实际参与人数，点数1～6，最高叫数不超过全桌骰子总数。斋只数所叫点数；非在叫2～6时计该点数与1，叫1时仅数1、不重复计数。
- 同为斋或同为非：数量增加可换任何点数；数量相同必须提高点数。非转斋数量不可减少、可同数量；斋转非数量至少增加2。此顺序为用户确认的本项目玩法，不引入其他地区的减半、劈骰或抢开规则。
- 依座位轮流叫号。当前玩家可开上家的叫号；全桌符合数量>=叫数（包括正好相等）则叫家赢，否则开者赢。只有这两人中的输家罚酒1杯，绝不重复结算。
- 达到酒量上限立即结束房间并进入现有醉后小剧场；房主也可手动结束。

## 一次行动一次请求

NPC回合一次请求返回该NPC的合法bid/open与全桌所有NPC各一句公开接话。模型只收到当前行动者自己的五骰，不收到玩家和其他NPC的骰子。玩家叫号先保存行动/留言，随后直接请求下家行动和全桌接话，不再单独调用玩家叫号接话接口。系统连续自动处理其余NPC，直到轮回玩家或开骰结束，每位NPC各一次请求。玩家主动开骰仍只请求全桌对已保存结果的接话，不把玩家骰子发送给模型。

同一模型调用承担多角色表演，提示词明确非行动者不知道ownDice；程序不会为每句发言额外请求。台词允许虚报、半真半假、含糊或感慨，不得输出内心独白、旁白或动作描写。常见整组报骰、精确自曝和心理活动会在显示/保存前以不泄露的一句台词替代；固定文本检查不保证识别任意暗号/隐喻。所有游戏结果均由程序裁定，模型不能改骰、定输赢或增减罚酒。

## 状态与失败保护

新PartyKind=liar，LiarRound.rulesVersion=liar-v1；完整dice、starter、turn、叫号moves与胜负随terminal.partyRooms保存并进入原本本地/云端/数据库分片及覆盖前恢复副本路径。旧文件不含新游戏时仍正常读取，未知规则版本和非法字段拒绝。旧页面可能拒绝新游戏备份，应先更新再导入。

玩家行动先落盘，pending标记等待下家行动/桌上接话。下家成功后在同一次写入中完成玩家pending并记录下家行动及全桌发言，玩家记录用replyWithNext=true指向紧接的NPC记录，避免重复显示同一组台词。导入严格校验该关系，旧记录没有该字段仍兼容。失败或停止后只从尚未成功的角色继续，不重摇、不重复叫号/开骰/罚酒；已成功的前一位不会重做。等待期间不能开始下一局。已结束的房间仅允许补最后一次接话和醉后小剧场，不重新开放游戏。

叫号界面使用数量输入＋斋/非选择＋1～6点数选择。最低数量根据参与人数、上家叫法和当前选择动态计算；小数、空值和低于下限均不能提交，离开数量框时校正到合法整数范围。修改模式/点数时自动补足新下限，最高斋6无法再叫时只允许开骰。正常NPC回合显示自动等待而没有“请下一位”按钮，只有错误恢复时显示重试。

请求中最近12次公开行动作为桌上历史；不发送剧情记忆、原始玩家人设、状态中的私有想法，也不通过HTTP raw诊断字段输出模型原文。角色性别和人设仍读取服务器权威字段与筛选后的世界书。
