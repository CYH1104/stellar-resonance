## 本阶段实现

原路径只允许 native-verification.invalid 并把最终出口锁在回环模拟模型。现在 createAccountRuntime 可显式接入 createNativeRequestRelay；未传入时旧实验限制保持，生产启动器没有因此自动切换。

新链路：学院现有鉴权与任务连接 → 请求专属目标地址／模型／凭据快照 → 原生私有编排 → 原生服务端 custom 适配 → 回环单次票据出口 → 已批准的 OpenAI 兼容服务。

- 每次任务独立绑定，不改全局 active profile。接口路径、Bearer 凭据、模型在异步初始化前固定；账号由服务端真实身份派生。
- 原生 worker 仅收到 256 位随机一次性票据，不拿真实 API Key。凭据只在服务器该次请求内存中存活，清理后移除；无新持久化字段、库或第二份存档权威。
- 出口必须提供目的地策略，在绑定和实际调用时分别核验。仅监听 127.0.0.1，固定 POST 路径；限制待处理数量、票据寿命与正文大小。重复票据不能二次请求，也不能取消已开始的合法请求。
- 取消、超时、编排错误、原生错误、HTTP 非成功、流结束与下游取消均清理请求绑定。最后一跳禁止跟随重定向；出口本身不隐式重试，不改变既有业务层明确格式纠正／手动重试逻辑。
- 模型请求思考关闭；不接受票据替换成原始 Key。不会把凭据写入原生助手页面、预设、配置文件、任务返回、日志或备份。原 native-client CSRF／Cookie 及 SSE 前缀检查保留。

默认真实出口使用平台 fetch，调用地址来自经过策略验证的任务连接。测试夹具明确替换最后一跳，把两个不存在的合成域名映射到本机模型服务，不拿模拟结果冒充真实服务商联调。
