## 用户行为

- API、预设、世界书及功能设置在独立草稿中编辑，显式保存才用于后续请求。取消恢复已保存值；应用内离开提供保存、放弃、继续编辑。单独保存某个 API 不会顺带保存其他未确认设置。读取模型与连接测试可使用草稿，不会激活草稿；有效列表清除已失效的模型，失败保留原选择。空模型配置可以保存，但不能生成。
- 人设和正文输入有单独的防抖草稿。输入提交失败保留输入，不发起模型请求。正文流式期间无周期性正文保存；完成提交正文与关联结果，停止、错误或截断保留未完成正文，不提前产生该轮记忆或终端动作。浏览器崩溃或刷新前尚未保存的流式内容可能丢失。
- 生成期间可浏览已有群聊、私聊和好友的空聊天页。已读操作延后提交，只确认实际看过的消息范围；不会把稍后到达的消息一起标为已读。
- 正文联动对每个有效已加入群处理 4–6 条消息；合法好友或已有私聊每会话 0–3 条，0 条无需补写。记录各群实际新增数，按稳定来源标识防重放，允许不同消息出现相同文字。保留旧协议文件的原规则以便读取。
- 正文成功保存后检查群消息缺额。只自动定向补齐一次，失败保留正文和已保存消息并显示手动入口；重试绑定原回合、变体、群与缺少槽位。好友申请或群动作缺失有诊断和定向补修，不把失败伪装成角色拒绝。
- 剧情建群与邀请入群为独立结构化动作。群可以原本存在于世界中，但用户尚未加入；同名群按身份区分。角色邀请需用户同意，加入后是普通成员；用户主动建群直接成为群主。NPC 自动管理员 0–2 人，管理员总上限 3 人，群主不占名额。待处理邀请不重复，拒绝后的冷却按完成的正文轮次计算，不由重试、刷新或换邀请者绕过。
- 接受邀请先保存成员资格，再生成欢迎消息。有效的部分消息保留；重试只补到至少 4 条，不重复加入或重复欢迎批次。
- 国王游戏新惩罚为 1 杯，最多结算 15 轮；醉酒结束优先于轮数结束。历史杯数不重算，旧超过上限的活动房间安全结束。每个醉酒角色串行生成独立双人小剧场，每篇至少 1200 个非空白字符，分别保留结果、摘要、失败草稿和重试入口；已完成篇不重发请求。原有每日占卜保持独立。

## 性能与验证边界

存档校验及旧好感迁移改为逐轮推进，避免每个历史变体重复从开头回放。生成分支使用受 Vue 同步观察保护的修订号，逐段检查不再反复序列化全部历史；包含人设、初始状态、开场、历史正文、变量和变体结构变更。流式显示约 48ms 合并更新；HTML 页面等待完整后挂载，折叠区域按需创建。终端和设置面板按需加载。检索复用 Worker 和按完整原文失效的词项索引，超时或失败回退本地计算。头像显示可使用缩小 WebP 衍生图，保存和备份中的原图保持原样。

同机合成 500／1000 轮（约 1.8／3.6 MB）测试中，校验由约 761／3313ms 降至约 16／31ms；新记录库完整写入约 31／57ms，单次输入草稿写入均值约 0.5／0.4ms（fake-indexeddb）。这些是合成基准，不是设备速度承诺；没有删除历史或缩小记忆范围。
