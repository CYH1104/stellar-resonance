# 好感度改为程序结算

新默认协议：模型返回 `<attitudes>{"changes":[{"id":"已有ID","attitude":"positive","strength":"small"}]}</attitudes>`。主接口模式在正文前输出，减少长正文截断造成漏返回；独立接口只输出此区块。服务器计算正负2或5，中性为0，限制范围 -100～200。模型不再编写变量路径、补丁或最终分数。

新 NPC 须有姓名和稳定 ID，程序 insert 登记为0后结算，已有角色不会重置。按同 ID 或唯一姓名复用角色。重复判断跳过；无效单项不影响其他有效项。缺失与无效判断明确提示并开放原有手动补全入口，不自动增加 API 调用。有效判断优先于旧 JSONPatch 和状态里的绝对好感，防止重复结算或旧快照覆盖中性结果。旧 MVU 协议继续兼容。

结算沿用当前稿件状态快照、切稿与撤回机制；反复读取、刷新不会重复加分。关系描述可选，未返回就保留既有关系，不阻塞好感度。

验证：服务端253项、前端344项测试通过；类型检查和构建通过。覆盖分块标签不泄漏、登记、上下界、重复角色、无效项、旧值覆盖、切稿和回退。

真实模型：agnes-3.0-flash，使用已授权公网 `/api/generate` 获取真实输出，再由本地新解析和结算代码处理。三轮依次是普通初见、帮助核对资料、故意损毁资料：同一角色 npc-ye-cheng，0 → 2 → -3；三轮都返回有效 attitudes。耗时约9.1、26.0、14.3秒。此测试不是新版公网部署验收。本机直连模型 ECONNRESET，因此采用游戏服务器作为调用通道；没有变更公网配置或正式存档。模型输出和私有报告位于 `.integration/attitude-real-public-report.json`，不提交。

部署后应使用新存档或原有独立测试存档复测。管理员若自定义覆盖了 ai.5，旧提示词仍可能生效；需要按编辑页当前提示词核实，不自动覆盖管理员编辑。
