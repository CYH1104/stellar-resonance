# 2026-10-24 终端桌面长方形头像与号码保存修复

## 基底与问题

基于main0ee2abb，修改前工作区干净，fetch核对无更晚伙伴提交。用户要求终端桌面头像为竖向长方形，并反馈立即保存时报“终端码只能绑定当前会话中已登记的角色 ID”。

## 根因与处理

- 桌面头像原样式为88×88并对按钮和图片设置圆形裁切。本轮改为88×120、4px小圆角矩形，图片圆角为0，保留contain和用户的缩放/位置设置。不修改上传图片、不重排界面、不改变私聊/群聊头像形状。
- 确认存在同报错的保存缺陷：ensureTerminalCodes会将新出场动态NPC的号码分配到initial.variables.终端码；保存调用parseBackup验证所有历史轮次时，早期楼层的MVU回放尚无这个NPC，但号码表已有其号码。validateTerminalCodeMap原本拒绝整个表中所有当前未登记ID，即使该绑定从before到after根本没变，也会让保存失败，并可能令历史状态回放跳过。
- 校验改为允许原样保留已经存在的历史/未来分支号码；仍拒绝新建未知ID绑定、改变或删除既有绑定、非法号码和重号。不删除历史号码，不把未来角色提前加入当前角色名单，不公开未知号码；terminalCodeBindings仍只返回当前已登记角色。
- 分配新码时也保留initial中的历史号码，避免与当前分支不可见的号码冲突。

## 验证

新增tests/terminal-code-save-regression.test.ts。修复前2项失败并出现截图同文案；修复后通过。覆盖新NPC分配后旧MVU回放、保存/导入、旧楼层不暴露未来NPC号码、切分支后恢复原号码，以及未知ID新建/变更/删除仍拒绝。

完整前端92文件474项通过；完整服务端345项中341通过、4项平台跳过。类型检查、生产构建及diff检查通过，已有bundle体积警告仍存在。

隔离浏览器实际计算桌面头像88×120、按钮圆角4px、图片圆角0px及object-fit:contain。截图在本机忽略的.integration中，合成头像用现有背景资源，不复制或上传用户肖像。

没有读取报错用户的实际存档或进行付费模型调用；复现证实代码有此缺陷，但若修复后仍保存失败，要以新错误核查其他损坏数据。
