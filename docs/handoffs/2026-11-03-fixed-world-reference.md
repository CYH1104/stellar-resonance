# 固定学院世界资源：第一阶段

依据用户确认的 `NATIVE_EXECUTION_PLAN_20261103.md` v2.1，先修正“每个存档创建一张角色卡”的实际偏离。本阶段不包含尚未发布的世界书统一页与助手 WIP，也没有启用私有编排或模型生成。

## 行为

- 新存档复用当前原生账号下 `stellar-academy-world-v1.png`，每个存档对应独立 JSONL 文件。公开资源只有固定名字及资源版本标记，不放私有作者设定。
- 世界资源由原版 characters/create/get 创建和核验；同名资源存在但标记／内容不符时停止，不覆盖已有角色卡。
- 打开旧存档不迁移；第一次保存旧工作区时，先读取并核对全部旧文件和页面基线，建立服务器账号内迁移副本，再逐个复制到固定世界资源下。
- 副本上传后回读校验；聊天复制后回读原始行数组；切换索引前重读旧文件和完整 settings，防止覆盖期间发生的独立编辑。
- 仅全部通过后切换原生 settings 中的聊天引用。存档 ID、JSONL 消息、全部 swipes、其他原生扩展、玩家人设、终端和资源关联不改身份；旧卡和旧 JSONL 保留，不自动删除。
- 副本／复制／设置失败或取消时不主动切换索引；保留原文件和已产生的副本。若请求在最终提交后断线，重新载入即可按已保存索引读取同一批聊天；不会回退覆盖并发修改。
- 与已有 settings/chats 保存共用账号队列，核对恢复租约归属；普通保存不能介入其他页面的恢复。迁移完成后客户端检查修订号及复制结果，再继续本次保存。
- HTTP 部署的聊天指纹使用现有原生摘要后备实现，不要求浏览器提供仅安全上下文可用的 `crypto.subtle`。

## 数据和备份

没有增加 Snapshot／BackupArchive 字段或浏览器数据库。固定世界卡属于可重建的公开运行资源，不把它或私有作者卡塞入普通存档包。

完整下载、导入、云编码、拉取覆盖及覆盖前恢复继续使用已有统一资料模型；本次迁移不改存档／人设 ID，因此不触发新的引用重绑。原设置中的人设、草稿、预设／世界书绑定、图片／资源引用均保留；API Key、仓库令牌、运行日志、原始模型输出的排除策略不变。

额外迁移副本使用原版 files/upload 写入当前账号的 `user/files/academy-world-recovery-<uuid>.json`。结构为 `{version:1,kind:'academy-world-reference',createdAt,settings,sources:[{reference,rows}]}`，保留迁移前完整原生设置和源 JSONL 行数组。未改写的预设、世界书及图片文件继续原位保留。

该副本路径登记在现有 `scope.recovery['native-world-migration']`，与 `scope.recovery.workspace` 分开。它是账号内迁移回退证据，不是普通下载格式；不能交给 `readCloudRecovery('workspace')` 或当作普通存档导入。普通“恢复上次覆盖”入口仍使用完整 BackupArchive 副本。管理员如需检查原始引用，可从此副本和原位旧文件核对；不要盲目把整份旧 settings 覆盖回来。
