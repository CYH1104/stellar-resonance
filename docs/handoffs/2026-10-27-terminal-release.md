# 9000 终端拆分与定时牌面：当前版本发布说明

基线 main：d76ce998a83db63b82aaceee6404614f5b89a5bc。用户在获知下面的未修问题后，明确要求“先上传吧”；本次发布当前版本，不能称为全部缺陷已修复。

## 本次内容

- 9000 顶栏启停手机；启用需明确配置并确认终端 API；正文与终端通讯独立请求，终端内可选先后顺序。停用、换接口、切档时拒绝迟到通讯，正文配置不再被可选终端接口阻塞。
- 自动通讯保留剧情与各会话历史、私聊知情范围及主动社交核验；阶段任务有独立目标和已提交事实，支持失败重试、续写及备份重载。
- 每日牌面取消30秒日期轮询，按下一日界线设置单次定时器；占卜页显示局部倒计时“距离刷新 HH:mm:ss”，隐藏时停止显示计时。界面无现实时间说明。
- 终端分支摘要缓存保留旧锚点逐位兼容，减少长档消息列表反复计算。
- 自动消息改用短ID，保留完整去重来源；真实生成后的下载/云端/导入/工作区分片/恢复副本往返通过定向测试。来源绑定使回退或修改行动后旧通讯退出当前可见与上下文，旧档记录仍保留。

这些是9000新功能。8807保持当前已确认发布快照与手机关闭；两端共用缺陷此前的CSS渲染修复已经发布，不因本次测试版功能重启稳定版。

## 已知未修问题（用户同意先上传）

在终端先行模式中，生成一轮后修改该轮玩家输入，再重新生成，已完成终端任务仍可能复用旧行动的事实，而不是为新行动生成对应通讯。原终端消息会因来源不匹配隐藏，但正文仍可能收到旧facts。

复现：输入“原行动”并生成 → 编辑该轮输入为“完全不同的新行动” → 重新生成。测试在 tests/codex-terminal-review-round3.test.ts；原断言保留，以 it.fails 标记当前已知失败。修复任务是使任务身份、ready复用、事实读取和重试共同校验行动来源；同一行动仅正文重试/续写仍不得重复调用终端。
