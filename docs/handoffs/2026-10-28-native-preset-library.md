## 已完成

- 原预设页支持多个玩家原生预设：切换、重命名、复制、导入为新增、删除、导出当前已保存原文。保留未知原生字段、条目深度、触发及顺序；当前原文只存一份，其他预设存在同一 `nativePreset.presets`，共用原工作区数据库和修订保护。最多 20 个，沿用总计 500000 字符的配置边界。
- 正文、记忆、终端、人设辅助、随机事件、论坛、总结、建议分别绑定稳定预设 ID；未绑定时跟随当前预设。删除前检查绑定，禁止无声破坏引用。API 配置路由仍沿用既有独立配置，不被预设绑定覆盖。
- 仅显式保存生效；整个库、绑定和未应用 JSON 都进入独立草稿，可刷新恢复，取消恢复完整基线。旧单预设配置和旧原文草稿继续可读。新草稿封装检查解码后的 rawText，凭据不能借字符串转义绕过；校验错误显示在编辑器内，不从 Vue watch getter 抛出页面异常。
- 每次请求同步取得所选原文快照，仅发送 `{version:1,preset}`，不会发送整个库。原生编排、出口传输与思考关闭保护沿用原实现；向量任务不注入文本预设，测活使用当前预设。
- 解决 e20 独立验收的旧数据阻塞：工作区根 archive、独立 editor-drafts 和 v1 旧数据库内的凭据草稿可隔离载入，原始字节留在本机，明确提示清理。清理前暂停写入、生成和备份；清理同时更新两个活动位置，保留剧情、人设、终端及普通草稿，有更新的安全原生草稿时保留它。旧 schema 升级不再用 archive 覆盖更新的独立草稿。
- 清理与原修订号、恢复锁、磁盘失败原子回退共用事务；成功后才解除标记。初始原生配置因旧草稿暂停迁移时，清理后恢复迁入，失败时不能把未落盘默认值直接用于请求。
- 多预设、绑定和安全草稿通过原 `BackupArchive` 参与全部下载、云端编码、文件导入、覆盖和覆盖前恢复副本；不存在第二配置库。旧文件缺字段继续保留本机，未知外层版本/字段、无效引用、重复 ID、含已识别凭据的数据写入前拒绝。文件导入及旧恢复文件仍严格校验，不擅自投影后静默丢字段；运行日志、原始模型输出、API/仓库密钥及云端本地图片政策不变。
