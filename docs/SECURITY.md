# 保密与访问边界

## 要保护的内容

作者全量世界书、未解锁人设、核心规则与正则；玩家 Key；各玩家的身份、聊天、变量、记忆与存档。

## 必须实现的控制

- 作者资料只存可信服务端，不进入客户端构建、静态素材、客户端 source map 或存档导出。
- 数据访问先校验玩家归属。作者导入、发布、回滚入口单独认证授权。
- 先按可见性与解锁状态筛选，再决定世界书触发；隐藏但未获授权条目不进入模型上下文。
- 模型只提出文本或受约束状态变更；服务端验证类型、范围、权限与事件条件。
- 上游入口由服务器配置 providerId 到固定 HTTPS 域名和路径。限制重定向、请求大小、参数及连接时长；禁止任意 baseURL。
- 玩家 Key 默认不落库、不记日志、不写网页明文持久存储；桌面可选保存使用安全凭据方案。
- 统一脱敏错误与日志；不返回内部调用栈、隐藏正文或完整私有 Prompt。
- 以两名玩家进行跨会话、跨存档、变量和解锁读写删除攻击测试。
- 正则与兼容输入均设预算，不执行任意脚本，未知字段报告而非静默接受。

## 能力边界

发送给模型供应商的片段会被该供应商处理。玩家控制 Key 或使用中转站，也可能查看该站的请求记录；白名单不能自动保证供应商不暴露 Prompt。需核验上游日志可见性与数据处理方式，再决定可注入内容。

已注入模型的设定可能通过反问或生成结果透露。提示词规则和输出过滤可以降低泄漏概率，不能承诺绝对保密。最有效的内容边界是根本不注入当前玩家不该知道的资料。不得以“动态加密拼装”宣称模型处理明文后仍然不可提取。

客户端混淆、打包或加密只增加逆向成本。为客户端解密而提供的内容，应视为最终可被提取。

## 内测发布门槛

私有资料不在构建产物；未授权入口不可读；玩家隔离测试通过；Key 与秘密不在日志；错误与取消行为可用；作者已理解模型与中转站的上述边界。
