# v0.14.0 动态MVU、小剧场补全、可选论坛回复

日期：2026-10-16（Asia/Shanghai）。上一版见 QA-v0.13.4.md。

用户明确好感度及char精神体OS由AI根据玩家人设关系和剧情生成，四个开启的小剧场均需有内容。旧实现硬性禁止好感度并丢弃模型affinity，safeState未回传旧数值，NPC的OS没有必填，小剧场及补修指令允许省略。新增dynamic-state测试先运行三项全部失败，修复后通过；不需要读取用户浏览器或调用真实模型来确认这些代码缺陷。

服务器提示要求首次按明确关系与剧情给好感初值，后续沿前值渐进变化，不虚构既往关系；暂用−100～100、0中性，在状态栏说明。affinity保留并回传下轮；实时生成路径对所有本轮在场角色要求有限合法好感，有已知精神体者要求非空spiritThought，拒绝未提供等占位。经典存档的校验仍接受原先有限数值，避免抹除旧数据。动态字段写入既有MVU状态更新、切稿回退、IndexedDB及备份；未相遇角色仍不列入好感列表。精神体种类继续来自已知设定，不凭空创造。没有接入任意酒馆MVU脚本运行时。

实时生成按开启配置校验每个小剧场：论坛至少一帖、群聊至少一条非空消息、同人文及custom非空正文。同人文仍限user与一名已知char，配对从明确人设判断；没有预先指定搭档时允许本轮新遇见角色，避免首轮错误固定第一名角色。漏项及无效动态字段触发只补状态，和截断共用最多三次额外请求预算。补修指令不再允许省略已开启位置；失败显示具体原因，不提交空窗为完整结果。

旧完成稿最新一轮新增补全状态和小剧场按钮（确认会调用剧情接口）；未完成稿仍用补修状态。成功更新新变量、保留正文、原骰点、原事件、已有论坛与有效小剧场；补全缺项。旧完整稿请求期间保留原outcome，失败也保留原有效状态。finishVariant对同稿事件记忆去重，手动只补状态不额外调用建议／摘要，避免重复费用和记忆。只修最新完整轮，避免悄悄改变后续分支。

论坛AI回复默认false，旧配置迁移也默认关闭、主API。设置→小剧场设置可开启并选择主／副API；只有开启时所选接口才属于必需配置，删除该副接口恢复主API。玩家评论先保存在本机；关闭不请求任何回复模型。开启后每条评论独立一次请求，服务端随机选已知char或普通校园NPC作为作者，发送公开帖／最近评论及该发言者必要设定，输出仅content并强制使用服务端作者，不能更新主线MVU或伪造状态。60秒超时、可手动停止；关闭功能、换路由／URL／模型／Key或切换存档会取消请求，迟到结果校验目标动态仍有效，防止串档。失败不自动重试，保留玩家评论并在该帖显示安全错误。AI评论保存作者、回复目标和kind，展示时不会冒充user，可备份恢复，回退按动态来源清理。显式思考内容被过滤，不直接返回作者定义原文，不在日志保存Key。后台接口为同源本机会话保护的POST /api/forum-reply。

验证：101项Vitest、92项Node测试，共193项通过；vue-tsc和生产构建通过。覆盖原缺陷三项红灯后转绿、完整四窗口及自动补修、旧affinity回传及新值保留、论坛默认零请求／指定副API／失败保评论／关闭取消／混合作者备份及回退不变更主线、实际HTTP论坛接口与参数拒绝、旧完整稿补全成功与失败回退、记忆不重复且不调用辅助模型。既有API本地恢复、骰子、状态与原Slate显示测试通过。未读真实Key、未进行付费模型调用或浏览器点击／视觉验收（此前浏览器访问策略限制仍遵守）。本轮仅更新本机，没有上传GitHub。
