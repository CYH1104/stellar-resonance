# 新角色注册与独立变量接口

本地变更基于 main 提交 762b924。

确认的问题：原 StoryDecoder 在处理同一响应的角色声明前执行 MVU 校验，新 NPC 同时出现在 status.characters 和 delta 中时可能因路径不存在被拒绝。旧独立状态调用使用 repairedMessages，未实际带入 ai.5 的完整 MVU 规则，并要求整套结构化状态而非纯变量输出。

修复：

- prepareMvuUpdates 优先执行显式新角色 insert，并从同一响应的有效 id/name 声明补注册；无完整身份的未知 ID 继续拒绝，不猜姓名。新角色缺少好感时默认0；已登记角色缺少好感且收到 delta 时，先 insert 0。既有好感保留，不自动每轮增加。
- 专用变量 API 使用现有 stateProfile 路由，保留旧配置兼容。界面改名“变量更新（MVU）”，可选任意配置好的副 API。专用请求包含正文、世界书、人设和当前完整变量，不包含用户预设；要求仅 UpdateVariable/Analysis/JSONPatch，不输出正文、小剧场、快捷回复。
- 主接口仍输出正文及已开启小剧场/快捷回复；独立变量模型失败不自动补调用，正文保留。仍兼容已有模型返回旧状态结构。
- STATE_MVU_OUTPUT_MISSING 区分没返回补丁；STATE_MVU_PATH_REJECTED 标识路径/操作拒绝；STATE_MVU_VALUE_REJECTED 标识结构/数值拒绝；变量折叠栏显示解释。有效空数组与拒绝/未输出不是同一回事。

验证：服务端248项、前端344项测试通过，类型检查和构建通过。模拟独立变量请求验证世界书和正文抵达副 API、新角色注册生效且只有一次副调用；无真实模型/公网部署测试。
