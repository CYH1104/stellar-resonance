# 顶部导航与对话操作菜单合并方案

状态：仅记录、待实施。本轮更新到最新 main fa539ec，不修改功能代码。顶部布局为建议；对话操作以用户最新要求为准。

## 一、顶部导航精简建议

桌面端建议一行：

```text
剧情  记忆  人物关系  地图    创作配置 ▾  更多 ▾    存档 ▾  返回学院
```

| 入口 | 收纳内容 |
| --- | --- |
| 剧情、记忆、人物关系、地图 | 保留直接入口 |
| 创作配置 | API 设置、预设管理、世界书、小剧场设置 |
| 更多 | 随机事件开关及编辑、行动建议开关、自动隐藏楼层、隐藏角色卡片、运行日志 |
| 存档 | 新建存档、切换存档、导入/导出 |
| 返回学院 | 独立按钮 |

- 去掉不连续的数字编号，使用清楚的中文名称。
- 游戏内只显示一套导航；外围重复的API/预设/设置入口在游戏内隐藏，返回学院首页后恢复。
- 下拉中的开关直接操作，显示开启/关闭状态；切换时保持菜单展开。编辑随机事件使用明确入口，不依赖长按或右键。
- 更多旁可显示新错误提示点，方便发现运行日志；提示不等于新增未读业务机制，具体清除规则实施时确定。
- 手机端使用当前页面名称及菜单按钮，展开后按上述分组显示，不挤成多排菜单。
- 保留所有功能、账号隔离和已保存开关偏好。变量变化统一在运行日志中查看，不重新增加剧情页显示开关。

## 二、对话操作菜单：用户已提出的要求

### 1. 删除问答改为回溯

显示名和相关提示统一为“回溯”。点击后必须先显示确认框：

> 确认回溯到本轮之前？
>
> 将删除本轮及之后的对话内容，并回退相关人物状态、记忆及小剧场记录。此操作无法撤销。

按钮为“取消”和“确认回溯”。取消、关闭弹框或按Esc均不操作。确认后才调用现有回退逻辑，不应因为改名就重新实现另一套删除规则。

实施时确认框应显示轮数/可辨识的输入摘要，并绑定原会话和楼层ID；确认前若会话或楼层已变化，拒绝操作，不能删除错误目标。生成中禁用；保存失败需保持或恢复原数据并明确提示。回溯与“撤回”区分：撤回把玩家输入放回输入框；回溯不额外回填草稿。

### 2. 重演改为重说

用户先说“重演删了”，同条消息后又说“重演改成重说”；本记录采用最后的明确要求：保留功能，改名“重说”，不再显示“重演”。

含义沿用现有重新生成回复行为：针对同一轮玩家输入生成另一份回复，保持版本切换规则。不增加额外自动调用；用户主动点击才调用，可能计费。已有后续剧情时，应保留/核对原有确认与后续失效提示，不能悄悄删除后续内容。

### 3. 正文完成后不显示继续续写

用户截图属于正文已完成的回复，此时菜单不应出现“继续续写”。判断依据必须是正文是否真正完成，不应只看整轮status：正文已完整但变量/小剧场失败，仍然不能显示正文续写，而应按实际缺项保留“补全状态和小剧场”等修复入口。

- 正文明确完成：隐藏继续续写；无论变量或小剧场是否仍有缺项。
- 正文明确未完成、有可继续文本且服务支持：允许继续续写。
- 失败且没有正文：只提供适用的重试，不提供空内容续写。
- 无可靠正文完成信息的旧记录：不得仅因变量缺失就判为正文未完成；采用保守处理，不自动调用，具体与现有完成标记核对后实施。

### 4. 完成回复的菜单示意

```text
编辑输入
回溯
撤回
编辑回复
重说
隐藏头像 / 显示头像
```

有缺失状态或小剧场时，按现有条件增加对应补全入口；正文完成的菜单始终没有“继续续写”。其他编辑和头像行为保留，不扩大本轮修改范围。

## 三、后续验收

1. 桌面及手机导航清楚，全部原功能可达，下拉可关闭，开关与原配置一致。
2. 剧情回复及输入区两个操作入口均使用新名称，无残留删除问答/重演。
3. 回溯取消不改数据；确认才删除正确的本轮及之后内容，状态回退正确；切换会话、目标变化及保存失败不会误删。
4. 正文完成且变量完整、正文完成但变量缺失、正文截断、失败无正文四种情况分别验证菜单。
5. 重说沿用稿件与后续失效规则，重试/补全不增加自动付费调用。

本轮没有执行以上功能变更或功能验收，仅记录方案并同步最新代码；后续实际修改前仍需先在Slack说明范围，上传后再发布提交、交接及测试结果。
