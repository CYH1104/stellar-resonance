# 状态栏与 MVU 适配 v0.10.0

左侧上方 user 只显示姓名、第一性别、第二性别、身份、精神体、精神体 OS，以及已遇到 char 的好感度。没有 user 内心想法栏目。身份在人设表与玩家设置中填写（最多200字）；身份和精神力等级以服务器作者资料（玩家以人设表）为准，模型与 MVU 只能读取，不能改写；仅用户显式修改人设后更新。没有资料显示未提供，不把整段背景当作身份。

user 的好感列表按当前有效剧情分支计算：初始在场或任一完整有效稿件中实际在场过的角色计为遇到；离场后仍保留。单纯提名、回忆、远程通讯、论坛发言、未完成或状态非法稿件不算遇到。切稿、编辑使状态失效或回退时重新计算，不使用无法回退的全局见过名单。

下方 char 卡仍只显示当前在场人物，保留双性别、好感度、内心想法、精神体与精神体 OS。AI 提交完整 presentCharacterIds，服务器验证并生成每名已知角色的 present 更新；玩家不能手选在场人物。身份、精神力等级、姓名、性别、精神体种类来自固定资料，不接受随意覆盖。

服务器当前没有正式好感度规则，不提交模型臆造的好感度数值。已遇到但没有值时显示未提供；不会以零代替未知。后续需要作者提供初值、范围、等级和每轮增减约束。

临时状态示例（不是完整酒馆 MVU 插件协议）：

```json
{
  "presentCharacterIds": ["角色ID"],
  "player": {"spiritThought": "已知精神体的可展示OS"},
  "characters": [{"id": "角色ID", "innerThought": "角色可展示的简短想法", "spiritThought": "精神体可展示OS"}],
  "event": "本轮事件摘要"
}
```

user 的旧 innerThought 字段可随历史备份保留，但不在卡片显示，也不再要求模型生成。只有完整合法的回复提交新状态，停止／断流保留上轮状态。原完整作者人设、世界观及世界书仍在服务器端。正式 MVU 路径及好感度规则仍需实际资料映射。

## 补修与旧存档

补全完整稿时，缺失或无效名单沿用本轮已有有效值；明确的离场仍可更新。增量以本轮开始前的状态计算，补修不会重复叠加。回复操作可展开补修前后的角色在场及好感度对照；非法历史轮次会留下最多 40 条去重诊断。旧正文、原始历史 outcome 和记忆不批量改写，读取时投影作者资料。旧记忆中已经产生的错误条目不会自动删除。
