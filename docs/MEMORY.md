# 每轮记忆与索引 v0.19.0

现有 summaryProfile 继续兼容，页面名称为“每轮记忆整理”。主 API 必填，副 API 可选；各任务的原选择和本机 Key 保存方式保持。

## 流程

1. 完整剧情与状态提交后，建立唯一 sourceTurn/sourceVariant 记忆任务，先存入本机；未完整剧情不建立记忆。
2. POST /api/memory 使用已选接口，读取本轮输入、完整正文、必要的前后状态及未履行约定。不发送作者私有卡、世界书、预设、论坛、小剧场、API Key 正文或角色内心和精神体 OS。
3. 整理人物、故事时间、地点、user/char 行动、所有得失、约定及好感度原因。程序从前后状态计算好感度和其他数值变化，不能由摘要模型虚构数值；未知时间地点明确标记。
4. 校验后以结构化字段保存，并生成可读文本；不再截取正文前220字，也不再自动每五轮汇总。
5. 向量开关打开时自动编码新记忆；向量、完整文本快照及模型指纹保存在浏览器。失败保留文字并显示索引失败，可单独重试。
6. 下轮用玩家输入、在场／提及人物、已有地点和近期事件构建查询；编码查询后在浏览器比较相似度并结合关键词。有效未履行约定固定带入；旧稿、未完成稿和未补记的旧截取记录排除。

## 一致性与恢复

- 每稿唯一记忆；同一正文／事实的状态补修不重复调用记忆。切稿／回退只使用当前有效来源，补记按剧情顺序传递约定。
- 记忆失败或主动停止保留正文与待补记任务，刷新后可恢复；不会为了记忆失败重演剧情。旧历史只在用户点击补记时调用模型，遇错停止，不无限重试。
- 结构化记忆可补充备注；备注更新后旧向量失效，避免可读文本与检索事实互相矛盾。普通手记仍可编辑／删除。
- 无向量、接口失败或 Worker 不可用时用本地关键词检索。索引与模型指纹及文本一致时才参与语义计算；改变模型或文字后显示待更新。
- 每条结构化记忆最多6000字，备注最多3000字；服务端请求体仍受2MB限制，长正文不截断成伪完整记忆，超过边界会明确失败并保留任务。单次记忆接口120秒超时，无自动收费重试。

## 边界

向量检索和模型提取不能保证永不漏项；重要约定、当前 MVU 与最近剧情共同提供上下文。当前语义索引是浏览器本地实现，尚未引入酒馆完整 MVU 脚本或用户世界书上传环境。
