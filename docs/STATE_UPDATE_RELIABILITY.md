# 状态栏与 MVU 更新可靠性

2026-10-18。

流程为：捕获控制块 → JSON 解析 → 在状态副本校验整个变量事务 → 接受有效结果 → 保存浏览器存档 → 从已提交结果渲染。正则负责定位，不直接改存档。不执行外部角色卡脚本。

## 错误处理

- 一个 MVU 操作违法，则拒绝整个变量事务；不再跳过坏操作后继续应用其余操作。角色名、精神体等不可改事实、危险路径和越界好感度均不能绕过校验。
- 多个非空变量块视为歧义，不重复应用；兼容多个空补丁。缺失变量保留旧值，空补丁表示无变化。
- 无效或截断状态块不丢弃正文、有效选项和有效小剧场。记录原始返回供核查，并返回 `stateUpdate`：变量状态、是否收到状态、正文完成标记、诊断代码。
- 回复下方区分“变量校验通过”“本轮变量无变化”“部分变量未通过校验，沿用旧值”和“正文尚未完整”。校验结果随备份保存，旧存档没有此字段仍可读取。
- 接受回复后先等待浏览器保存，再检查记忆整理轮数。写入失败明确显示未保存，不把校验通过当作持久化成功。
- 手动补状态不会把补状态响应的正文再次拼接进原正文。同一变体重复提交不会重复累加好感度。

## 调用规则

普通前端始终使用单次状态调用策略，格式失败不自动补修或重试。只设主模型时，主模型一次返回正文、开启的小剧场、选项与状态。独立设置 MVU 副模型时，主模型负责正文、小剧场与选项，副模型仅处理状态变化；副模型失败保留主模型输出和旧状态。

向量索引保持独立，整理记忆仍在达到既定轮数时调用。手动续写、重演、补状态属于用户主动请求。兼容测试保留旧接口显式关闭单次策略时的受限续写行为，不用于当前普通前端。

默认英文规则采用增量更新，并把状态与变量补丁示例分开，避免状态快照重复覆盖好感度增量。支持原有 SR_STATE、SR_DONE 以及当前分块格式。作者保存的自定义内部提示词仍优先，不强制覆盖。

NPC 好感度有效范围为 -100～200；负好感关系线淡红色。数据和边界详见 AFFINITY_RULES.md。

## 验证与限制

208 项服务端测试、251 项前端/领域测试、TypeScript、生产构建、18 项隔离浏览器检查通过。覆盖跨片段捕获、坏事务整体拒绝、截断、重复提交、主副接口次数、正文保留、备份恢复和负好感关系线。测试使用模拟模型响应，没有消耗用户 API。

不能保证外部模型每次都返回合法状态；本次保证代码能够校验、保留可用内容、沿用旧值并报告失败，避免静默损坏。没有直接登录或更新用户服务器。
