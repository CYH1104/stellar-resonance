# v0.12.0 状态格式自动补修与具体诊断

日期：2026-10-16（Asia/Shanghai）。上一版记录见 QA-v0.11.2.md。

已复现：正文与结束标记完整，但隐藏状态 JSON 不合法时，旧流程直接报 INVALID_MODEL_STATE，既不补修也不指出类别。新增回归测试在旧逻辑下失败，补修后通过。

格式错误会切换到只输出完整隐藏状态的请求，保留此前正文、原行动、卡片、接口参数与骰点。服务端进入隐藏状态模式，模型错误复述正文也不再输出公开 delta；前端同样在补修模式忽略 delta。截断续写和补修共享最多3次额外调用，根取消信号阻止下一次调用，独立超时沿用180秒。认证／限流等不可恢复错误不继续消耗预算；尺寸与输入限制依旧生效。骰子结果缺少或方向冲突保持直接拒绝，不靠修改元数据宣称新的剧情后果。

JSON、额外字段、在场名单、事件摘要、玩家／角色字段、论坛、小剧场、缺少玩家精神体 OS 等分别映射为固定代码。耗尽时 STATE_REPAIR_LIMIT 附带安全 reasonCode；不回传原 JSON、未知字段值、角色定义、模型错误正文或Key。标准JSON代码围栏在隐藏块内可去除后严格解析，不执行代码。

旧失败稿提供“补修状态”按钮，仅在正文确已完整时使用；复用当前稿件和骰点，传 continuation.mode=state，首个上游请求就只生成状态。不会再次调用向量检索，不重写正文；新稿内容仍只能在校验后提交一次状态、事件记忆，再调用建议／摘要。失败稿、正文和上一轮状态持续保留。正文未写完继续使用“继续续写”。

新增测试覆盖隐藏JSON错误后补修成功且重述正文不泄露、混合续写与补修的共享预算、补修中停止、手动仅补状态、三次失败原因、标准围栏零额外调用、字段错误的安全分类；HTTP走实际路由验证补修、无delta的手动状态模式和非法mode拒绝；网关不展示未知代码文本；工作区保留原稿ID、正文与骰点且记忆仅一次，失败不提交。

最终检查：80项前端／工作区／SSR测试，72项Node服务器／模型测试，共152项通过，类型检查与构建通过。本机预览重启后health确认v0.12.0，首页200，地址 http://127.0.0.1:5173/。
