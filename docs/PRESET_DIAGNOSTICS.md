# 如何判断预设是否参与了请求

白名单管理员账号生成剧情后，进入「14 运行日志」，展开「开发者模式 · 预设与输出检查」。不增加模型调用；普通账号不会从服务器收到这些诊断事件。

开始请求记录包含：

- 条目名称和标识、是否加入请求；关闭条目、关闭分组、占位条目、未列入顺序、触发条件不符和独立状态模式过滤分别注明原因。
- 已加入条目经宏展开后的文本、角色、位置、深度、顺序、字符数，以及在实际最终消息列表中的编号。
- 实际发给主剧情接口的采样参数和最终消息角色顺序。

条目预览单项最多 16000 字符、每次请求合计最多 80000 字符；截短会明确提示，不会因此截断实际发送给模型的条目。诊断只保留当前页面最近 40 条，刷新或清空后移除。

生成结束记录显示状态接收、人物更新、快捷回复、论坛、小剧场位置以及兼容处理代码。出现兼容记录时，部分字段可能沿用旧值，应结合原始格式日志核查。

这些记录证明条目是否进入请求，不证明模型一定遵守，也不声称能判断模型内部是否思考。检查遵守情况时，对照已发送条目与正文、状态、按钮、小剧场等实际返回。这里不展示模型隐藏思维链。

# 内置规则与状态格式

内置默认规则使用精简英文，要求可见剧情及状态文本使用自然中文、直接进入场景，不输出助手式确认、计划或解释。状态协议包含实际 JSON 示例，沿用当前已知角色 ID；示例仅演示结构，不设定本轮在场名单或剧情。

状态关闭时，示例不包含人物状态；小剧场和建议仅按启用情况追加示例。世界书、用户预设、历史、人设与记忆原文不会被翻译。管理员自行保存的模板覆盖也会保留；需要使用新版默认规则时，可在管理页对应条目点击「恢复内置默认」并保存。
