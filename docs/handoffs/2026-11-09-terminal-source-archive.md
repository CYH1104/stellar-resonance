# 9000 有未读数但聊天页也空白：独立终端消息被剧情同步误归档

基线 main / 工作树均 dc4c8d1，Codex 持棒并已读 agent-hub。用户确认本次不是仅列表摘要错误：8 条未读所在群点进去也空白。此前预览统一补丁没有复现该条件，不能算已解决这个故障。

## 根因和修正

`syncStoryGroups` 把所有带 source、且不是 main: 前缀的消息都当成小剧场消息归档。独立终端的 auto: 群聊/私聊以及 welcome: 入群消息不在小剧场来源集合内，因而被设为 archived=true。记录、文本和未读计数都还在，显示过滤却同时隐藏列表摘要和聊天内容。终端组件加载后的同步 watcher 可直接触发，无须切换剧情分支。

- 同步只归档由剧情群来源管理的消息；main:、独立终端、入群欢迎和无关外部来源分别保留其所有权。
- 对 auto: / welcome: 已有的误归档标记做幂等恢复。只解除该错误标记，不删消息、不重生内容、不改未读计数；原 anchor/origin/分支与知情限制继续生效，旧分支不会因此混回当前剧情。
- 同步在加载、正文生成及备份操作期间等待，空闲后再执行；写入时在同一队列内读取最新终端副本，避免预先克隆的快照覆盖期间新到消息或用户资料修改。
- 保存失败按响应式对象的真实身份判断并回滚，阻止“内存已修好、实际未保存”；同一失败来源不因 working 状态变化无限重试。
- 回滚修正首次使两个占卜既有测试失败：原测试要求未保存的牌面仍锁定在内存、且不得调用解读 API。本轮显式保留仅 pending 的原牌面，未声称它已落盘；重试先保存同一副牌，再请求解读。其他终端写入保持正常回滚。

没有新增持久化字段、数据库或备份版本；只修复既有 archived 标记及本机同步逻辑。导入/解析本身不改历史标记，打开终端后受控修复。下载、云端上传、导入、拉取覆盖和覆盖前恢复仍沿用完整采集入口；人设/草稿/预设/世界书/全部通讯保留，日志及原始输出、云端本地图片和密钥排除规则不变。
