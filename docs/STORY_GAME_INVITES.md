# 剧情游戏邀请与观战

2026-11-28 修正邀请入口。新增功能仅9000，8807保持现有稳定版本。

## 使用方式

正文中角色明确想玩或发起斗地主、日麻、六人狼人杀、十点半、大话骰、真心话大冒险时，随本轮终端通讯请求生成游戏邀约。终端桌面显示「朋友的游戏邀约」，先联系发起者和朋友取得各自同意，人数足够后玩家可参加、进入观战位或婉拒。相同来源不重复生成，否定、假设或过去事件不触发。

角色从当前存档已知角色中评估自己可能认识的朋友；已知角色、玩家好友、同学或同事不自动等于发起者好友。正文邀约先保留发起者一人，正文与终端更新完成、工作区空闲后自动继续协商，无需打开终端或用户要求组局。每条邀约在当前工作区生命周期自动尝试一次；错误不会循环重试，桌面可手动继续未完成的回应。正文邀约确认后玩家参加时，邀请卡已标明的最后一位替补让座；观战时全部由角色入座，玩家不占席位。不为凑人数创建陌生人。游戏开始由玩家点击开始观战/继续推进。不在关闭页面后无限后台生成，也不补造不存在的历史对局。

斗地主和日麻在当前牌桌自动出牌，可以暂停、退出后继续。其他游戏复用已有阶段推进。历史小局可在观战页选择回看，查看历史时暂停当前自动出牌；桌面「角色对局记录」可重新进入已保存的房间。

## 在已有房间拜托好友代邀

首页不再提供「请谁组局」「游戏」「我的席位」请求表单。旧版本已保存的用户请求仍可查看和继续，不删除历史记录。

玩家自己进入六类游戏的入口时，先创建等候房间，允许只有自己，随后在房间里直接邀请好友；当好友不够、有人拒绝，或想请不在自己好友列表中的已知角色时，展开「拜托好友邀请」。选择受托好友、可选指定对象和500字以内留言。

1. 受托好友独立请求一次终端API，按自身资料和知情记忆决定是否帮忙、可能认识谁。拒绝、没有合适的人或不认识指定对象都是有效结果。受托人不会因此自动占座。
2. 只邀请该好友实际选择的对象，每人单独一次API接受或拒绝。指定对象时不能擅自换人，已入座角色不能重复邀请，不能超出空位。任何人拒绝都不会自动重问。
3. 已接受者加入同一个等候房间；人数不足继续等候，不创建另一场游戏，也不提前发牌或发狼人杀身份。人数够后玩家确认进入游戏。
4. 已有尚未开局的玩家聚会房间可补充邀请，保留原房间ID、已接受者、名称、氛围，以及旧的拒绝/未答复记录。已开始对局不能换人。角色主持房间仍按原邀约参加或观战。

协商过程中每一步保存；停止、断网或刷新后，继续只请求尚未保存回应的人。模型失败不会当作角色拒绝。切换房间、存档、分支、API、覆盖恢复或其他页面写入后，迟到回应不能覆盖当前数据。受托好友列表只来自玩家的真实好友，不假定该角色认识所有人，也不把推测关系写成已确认好友。

代邀请求数量为受托好友1次加实际被邀请人数；直接邀请为每位好友1次。被邀请者仅收到自己档案、知情记忆、公开入座名单和邀请信息，没有其他人的秘密、私下判断或答复。模型原始输出不返回前端。

## 知情与记忆

- 观战组件仅接收公开投影，不接收牌堆、角色暗牌、隐藏骰子或策略参数。日麻只公开牌河、副露和规则允许结算亮出的牌。
- 狼人杀观战全程不展示角色身份、狼队密谈、女巫药物和预言家查验；死亡、公开发言和公开结果可见。游戏结束也不公开身份。
- NPC请求继续经各游戏服务端校验，精确匹配参与者与请求角色；狼人互认使用原有私有视角，其他角色不获得全局身份表。
- 角色记住实际参与者、剧情时间和已确认结果。玩家在观战位时明确标注「玩家仅观战」，没有假装参与或醉后独处小剧场。
- 邀约回应写入知情范围内的记忆，明确是邀约协商，不证明好友关系或已完成游戏。发起者知晓每个回应；被邀请者不能获知其他人的答复。
- 正文邀请绑定已确认正文的锚点、回合输入指纹；用户主动请求绑定当前剧情锚点；回退到其他剧情分支时邀请与对应房间隐藏。

## 保存与兼容

新增可选 `terminal.gameInvitations`，新条目 `version=2`，嵌套 `recruitment` 保存来源、请求、参与模式、发起者判断、候选依据与逐人答复；兼容旧 `version=1` 邀约；partyRooms / werewolfGames 使用可选 `hostId`、`invitationId` 标识角色主持的房间。旧文件缺少字段继续可读，新版未知字段或版本在写入前拒绝。

完整本地下载、云备份、导入换ID、覆盖前恢复副本保存全部邀约及游戏历史。云端图片和密钥过滤保持原规则。只对 invitation/lobby.anchor.key 精确放行锚点键。合成测试覆盖真实导出/云恢复/替换/追加导入/撤销、写失败与跨页面冲突。

国王游戏沿用原入口，本次没有改造为角色主持或观战。

等候房间存于可选的 `terminal.gameLobbies`（条目version=1），记录剧情锚点、初始入座名单、每次代邀与逐人答复、原房间及最终对局ID。房间和对局ID均在会话内部，追加导入更换会话ID时继续保持内部引用；旧文件缺少字段继续可读，未知版本/字段先拒绝。完整备份与恢复包含这些记录；没有新增独立数据库或localStorage配置。
