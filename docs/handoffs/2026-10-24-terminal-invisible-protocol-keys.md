# 2026-10-24 自动群聊被零宽协议字段名丢弃

## 问题与确认范围

用户提供 SR_STATE：terminal 中有两组群聊，但终端未出现；player.spiritThought 与 groups[].topic 字段名分别夹入 U+200B（sp\\u200BiritThought、top\\u200Bic）。当前基底 main 2436a5b，fetch 后没有更晚伙伴提交，修改前工作区干净。

确认根因：JSON语法合法，但键名不等于协议字段。cleanTerminalBatch 读取 group.topic 得到 undefined，严格校验失败；StoryDecoder 捕获异常并输出 STATE_TERMINAL_RETAINED，不携带 outcome.terminal。客户端随后没有自动通讯可应用。因此此样例是“已生成但被校验丢弃”，不是没有随主API生成。player 中受污染的键同样无法匹配 spiritThought，原值保留。

不能从片段判断真实请求中的群ID/成员元数据是否另有不匹配，也不能仅凭本段没有 SR_DONE 就断定完整回复截断；这些仍按原校验处理。

## 修复

- 新增纯函数 normalizeProtocolKeys：只对明确允许的协议键移除 U+200B/U+200C/U+200D/U+2060/U+FEFF 与首尾空白，不能猜拼写、大小写、角色ID或任意自定义键。
- 应用于状态协议根字段、角色/玩家字段、set/keep包装，以及终端群/消息/主动私聊/好友申请/课程结构字段。
- 输入对象不原地修改；字符串值、中文正文、换行、号码、ID、变量路径和用户自定义键原样保留。未进行全局正则清理正文。
- 标准字段与规整后的别名内容相同可合并；内容冲突时丢弃冲突字段、记录 STATE_FIELD_CONFLICT，不能按先后顺序静默选值，第三种拼法也不能恢复已冲突字段。
- 正常兼容记录 STATE_FIELD_NORMALIZED，并新增中文校验说明。终端层警告沿用主请求诊断链路，无新增API调用。
- 角色/群ID权限、固定群元数据、数量、成员发言与好友限制、课程字段类型等严格检查保留；不把任意格式问题一律当正常输出。
