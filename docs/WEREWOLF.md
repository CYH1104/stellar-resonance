# 六人狼人杀（9000测试版）

2026-11-26 用户确认：先把现有斗地主、日麻发布8807，再在9000开发狼人杀。首版仅六人（玩家与五位已添加好友）；未来人数扩展不在本次规则内。

## 确定规则

- 2狼人、2村民、1预言家、1女巫，程序主持，无警长。程序随机发身份并先保存，重试不重新洗身份。
- 屠城：狼人全部死亡则好人胜；全部好人死亡则狼人胜。人数持平不判胜，神职或村民一边全灭不判胜；同夜双方全灭先判好人胜。
- 狼人互认，可刀自己或队友，不空刀、不自爆。
- 预言家查验存活的其他人，只获得狼人/好人，不知道具体神职。
- 女巫一救一毒，每夜最多一瓶；仅首夜可自救。解药耗尽后不知道刀口，被救者可能是自刀狼，不能当作查验金水。两药耗尽后程序跳过用药，无额外模型调用。
- 夜间行动统一结算，天亮只公布死亡名单或平安夜，不公开死因。
- 首夜死者和白天投票出局者有遗言，其他夜晚死者没有遗言。
- 按座位顺序发言。投票可弃票、不可自投；最高票平票者补充发言，其他存活者复投，再平票、全弃票或无人有投票资格时无人出局。
- 死亡头像变灰并标“死亡”。整局竖屏，中间公开聊天，左右各三席。
- 不自动翻身份，终局仍不展示全体身份。公开发言允许主动报身份、诈身份、说谎；这些是玩家主张，不是系统确认。

## API流程与信息隔离

| 阶段 | 调用数 | 合法输入与决策 |
| --- | --- | --- |
| 发身份 | 0 | 本地随机并保存，各角色每次请求注入本人身份 |
| 狼队商议 | 有存活NPC狼时1次 | 每个NPC狼各给目标与一句理由；人类是存活狼时由人类最终定刀，否则同一响应给最终刀口。仅剩人类狼时0次 |
| 查验 | NPC预言家存活时1次 | 只选目标，程序得出阵营；人类预言家手选 |
| 用药 | NPC女巫存活且有药时1次 | 狼刀确定后，输入剩余药和合法刀口信息；人类女巫手选 |
| 天亮公告 | 0 | 程序统一结算并公告 |
| 日间发言/遗言/平票发言 | 每个应发言NPC各1次 | 串行请求，后一位能看到前一位已公开发言 |
| 投票/复投 | 每个有投票资格NPC各1次 | 并发、各自独立；全部完成后公布票型，不能看到未公开选票 |
| 结束 | 0 | 程序判胜并保存时间、参与者和公开结果，不揭身份 |

通常夜晚最多3次调用、两个等待阶段：狼队和预言家可并发，女巫等待最终刀口。人类为预言家/女巫可省对应调用；人类为狼且还有NPC狼时仍有一次商议，因此不承诺人类为狼必定少于3次。这里计业务调用，连接预检和用户明确重试另计。

狼人请求只含狼队身份；预言家请求只含自己的查验；女巫请求只含自己的药和合法刀口。其他人只有本人身份与公开日志。服务端使用独立白名单协议，不追加普通终端的全局状态、世界书、通用记忆或其他人的私人资料。角色初始性格可注入。公开聊天按不可信游戏内容处理，角色可推理或撒谎，但服务端不提供未知身份。

这是单人本地存档游戏的角色视角隔离：规则引擎和可恢复存档持有完整身份表，界面和正常模型请求只用投影。不是面向修改浏览器存档的对抗多人防作弊系统，也无法保证模型每句推理正确。禁止把完整存档传入生成请求来“假装各自不知道”。

## 保存、恢复与失败

session.terminal.werewolfGames 是可选数组，version=1。每局保存初始身份、座位、剧情分支锚点、开局时间和已提交动作；读取时重放规则校验。界面瞬时输入不持久化。新增内容随完整备份、云端备份、覆盖前恢复副本与导入换ID往返；旧存档缺少字段仍可读，未知版本/字段/非法动作拒绝写入。

保存失败回滚该次行动及派生记忆；跨页面冲突不静默覆盖。角色成功回应先保存，失败仅补未完成部分。切换存档、分支、终端API或离开游戏时停止当前请求，晚到响应不写入。格式错误不自动发第二次修复请求，显示可继续重试。角色在每次游戏请求中重新获得自己的身份和查验，供应商无须维持会话。

通用剧情/聊天记忆只记录参与时间、参与者和公开胜负；不传播身份表、刀口、药品或未公布选票。游戏事实按剧情锚点排序，同锚点兼顾牌局与狼人杀，避免旧狼人杀记录挤掉最近牌局。
