# 剧情游戏邀请与观战

2026-11-27。新增功能仅9000，8807保持现有稳定版本。

## 使用方式

正文中角色明确想玩或发起斗地主、日麻、六人狼人杀、十点半、大话骰、真心话大冒险时，随本轮终端通讯请求生成游戏邀约。终端桌面显示「朋友的游戏邀约」，先联系发起者和朋友取得各自同意，人数足够后玩家可参加、进入观战位或婉拒。相同来源不重复生成，否定、假设或过去事件不触发。

角色从当前存档已知角色中评估自己可能认识的朋友；已知角色、玩家好友、同学或同事不自动等于发起者好友。正文邀约先保留发起者一人，点击「请他联系好友」才开始协商。正文邀约确认后玩家参加时，邀请卡已标明的最后一位替补让座；观战时全部由角色入座，玩家不占席位。不为凑人数创建陌生人。游戏开始由玩家点击开始观战/继续推进。不在关闭页面后无限后台生成，也不补造不存在的历史对局。

斗地主和日麻在当前牌桌自动出牌，可以暂停、退出后继续。其他游戏复用已有阶段推进。历史小局可在观战页选择回看，查看历史时暂停当前自动出牌；桌面「角色对局记录」可重新进入已保存的房间。

## 请角色邀请自己的好友

终端桌面展开「请角色邀请自己的朋友」，选择已成为玩家好友的发起者、游戏，以及「我也参加」或「我只观战」，填写最多500字的请求并发送。

1. 发起者独立请求一次终端API，可以拒绝，或根据本人人设、已知记忆评估可联系人数、候选关系及本次优先邀请的人。允许没有合适朋友，也允许选不够。关系依据区分profile、memory、inference；界面人数始终标为估计，不能把推测自动写成已确认好友。
2. 按发起者选择逐个向好友请求一次API，每个人独立决定接受或拒绝。拒绝不会自动重问，也不会当作已入座；不默认所有候选都接受。
3. 所有被选好友答复后，人数充足才开放参加/观战按钮；否则显示未凑齐人数，不创建游戏房间。玩家参加的请求预留一席，观战则需凑齐整桌NPC。

每次回应立即保存。停止、断网、刷新后可以继续，只补未保存的回应。API故障和格式错误不会变成角色拒绝；不自动修稿或额外调用模型。切换存档/分支/终端API、并发终端修改或覆盖恢复会阻止旧回应写入。已有拒绝/人数不足记录可以收起，或发出新请求。不会修改玩家自己的好友列表。

请求数量是发起者1次 + 实际邀请人数（最多5人）。玩家参加斗地主通常2次，观战斗地主通常3次；日麻分别3/4次，狼人杀分别5/6次。发起者拒绝时仅1次。使用保存的终端API配置。

被邀请者只收到自己的档案、知情记忆、发起者公开身份及邀请内容，不收到发起者好友分析、其他人的答复或隐私资料。模型原始输出不返回前端。

## 知情与记忆

- 观战组件仅接收公开投影，不接收牌堆、角色暗牌、隐藏骰子或策略参数。日麻只公开牌河、副露和规则允许结算亮出的牌。
- 狼人杀观战全程不展示角色身份、狼队密谈、女巫药物和预言家查验；死亡、公开发言和公开结果可见。游戏结束也不公开身份。
- NPC请求继续经各游戏服务端校验，精确匹配参与者与请求角色；狼人互认使用原有私有视角，其他角色不获得全局身份表。
- 角色记住实际参与者、剧情时间和已确认结果。玩家在观战位时明确标注「玩家仅观战」，没有假装参与或醉后独处小剧场。
- 邀约回应写入知情范围内的记忆，明确是邀约协商，不证明好友关系或已完成游戏。发起者知晓每个回应；被邀请者不能获知其他人的答复。
- 正文邀请绑定已确认正文的锚点、回合输入指纹；用户主动请求绑定当前剧情锚点；回退到其他剧情分支时邀请与对应房间隐藏。
