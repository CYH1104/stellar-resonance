# 校园论坛与随机事件

## 论坛创作

内置论坛规则采用校园微博语感：每轮 1—3 条动态，每条 0—3 条短评论。仅借用正文的氛围、情绪余波、校园生活侧面和公共服务需求，不复述正文、不引用私人对话、不暴露人物身份或私人关系。官方账号只提供克制的服务、秩序、活动提醒。

默认内部规则为英文，展示内容为中文。论坛仍使用原有 `<forum>` JSON 数组，与正文、状态栏、MVU、快捷回复在同一响应中输出。新增可选 `type`（类型）和 `time`（剧情内相对时间）字段，界面在昵称下显示。时间不是服务器实时时钟。

兼容层接收常见字段别名、中文字段、简短字符串评论及转义换行，再逐项校验；不执行模型返回的脚本。新生成内容限制为三条动态、每条三条评论，历史存档保留原内容。论坛正文保持文本转义展示，不让 HTML 或正则内容破坏状态数据解析。既有正文正则处理链不变。

仅精确匹配旧默认规则的小剧场设置会自动更新；用户自行修改的论坛要求和服务器内部提示词覆盖不会被重置。如管理员以前保存过 `feature.forum` 自定义内容，可在学院档案编辑的内部 AI 提示词中按需更新或恢复该条默认值。

## 随机事件

- 顶栏“12 随机事件”：单击开关，长按约半秒打开提示词编辑；桌面右键或 Shift+F10 也可打开。
- 输入事件创作要求并点击“保存提示词”，自动随当前浏览器的工作区设置保存，也包含在导出备份内。留空使用内置规则。
- 此处编辑事件创作要求；事件概率、类别、骰点由脚本控制，输出协议仍由内置规则约束。
- 只有本轮触发事件时，主剧情请求才附带这些要求。续写、补状态、未触发时不附带。随机事件使用独立模型时，该候选请求也接收要求；跟随主模型时不增加候选请求或补救请求。
- 卡片优先显示已发生的骰子事件结果，其次显示有效事件摘要。若模型只返回通用兼容状态文字，改为显示本轮实际正文片段，不把“状态已更新”当成事件内容。
