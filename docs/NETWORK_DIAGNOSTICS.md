# 模型列表连接排查

2026-10-15 本机反馈“无法连接模型服务”。通过正在运行的 /api/models 以刻意无效的测试凭据复现 MODEL_UNREACHABLE；从受限执行环境发出的 Node 请求返回 EACCES，而正常联网权限下同机 DNS 与 HTTPS 均可用。将已记录、已校验的本项目服务停止，再用正常网络权限启动，原后台调用路径返回 UPSTREAM_AUTH，证明请求已到达服务商。未读取用户 Key、未发送卡片或剧情、未进行模型生成。

同时确认用户所用服务根路径的 /models 返回网页；正确的 /v1/models 返回 JSON 认证响应。基础地址应填写包含 /v1 的服务商 API 基址。不能仅凭首页可打开判断模型接口地址正确。

脚本 scripts/check-model-network.mjs 仅检查传输，不使用真实 Key，不打印响应正文：

- node scripts/check-model-network.mjs https://你的服务/v1：不带认证读取模型列表，检查 DNS、HTTP 状态和内容类型；此命令本身也需要正常出站联网权限。
- node scripts/check-model-network.mjs https://你的服务/v1 --through-local：通过本机5173后台请求模型列表，使用刻意无效的测试凭据；收到认证拒绝才视为传输链路通过，不代表真实凭据已验证。

双击启动预览.bat 可从用户正常 Windows 环境启动。代理、证书或防火墙依然可能影响后续其他服务；不要关闭证书校验。由开发工具启动长驻服务时，必须确保该进程有用户所需的出站联网权限。后台重启后本机会话需要刷新，v0.8.0 开启本机保存后 Key 自动恢复（旧版未保存的 Key 需填写一次）；存档保存在浏览器，后台重启不删除存档。
