# 单次生成的截断诊断与手动续写

基线 main：9f8ca6b71481aec19a48894b75b998bee725abec。

用户提供的 STATE_COMPAT_RECOVERED 记录只含正文和缺失状态码，没有上游结束原因，不能据此断定预设、Token 上限或网络中的哪一个导致了这次中断。内置协议没有要求 Interleaving 标签，也没有向上游设置 stop 参数。本轮不修改人设、预设或提示词约束。

已确认并修复的代码问题：singleStateCall 模式可能在部分正文已经到达后，吞掉流中断或接受 finish_reason=length 的无结束标记回复，随后把状态兼容恢复作为正常完成。现在明确的上限、过滤或中断会保留为未完成稿，保留收到的文字，原状态和记忆不提交，不发起额外模型调用。明确带完整结束标记的有效输出继续兼容保存；缺少标记的普通旧格式 stop 也保留兼容，不推测其是否语义上被截断。

普通运行日志新增“上游结束信息”区块：上游结束原因、输出/推理字符数、请求输出上限。以前该诊断只在开发模式可见。未提供原因时明确显示“未提供”。日志仍使用现有 note 区块，并继续排除在存档备份之外。

未完成调用保留已有 stateUpdate 元数据以支持手动续写；不引入新持久化字段。旧稿即使曾标为 complete，只要明确 storyComplete=false，也显示“继续续写”。没有这一明确标记的旧稿不推断为截断。正文和原稿保留，新增导出导入回归覆盖未完成标记。

验证涵盖单次输出上限、传输断开、过滤、普通旧格式 stop、完整结束标记兼容、零自动重试、前端半成品保存与备份往返、普通运行日志及旧稿续写按钮；完整前后端与类型/构建检查按发布流程执行。
