# 2026-10-24 历史整块变量快照导致终端码保存失败

## 背景与范围

用户在公网仍报“保存失败：终端码只能绑定当前会话中已登记的角色 ID”，且刷新后进度回到上次保存。已读频道：伙伴曾部署106a927及后续8258dac，因此不能继续仅归因未部署。先在干净工作区同步最新main a7c13c0；本轮只改src/domain/mvu.ts与保存回归测试，不涉及伙伴的群聊伴随字段、头像或终端UI。

## 已复现的根因

旧回合使用replace /custom保存整块自定义变量快照，该快照没有后来新增的终端码表。ensureTerminalCodes将程序生成的号码写入initial后，重放旧/custom快照会使next.custom缺少终端码。validateTerminalCodeMap将缺失号码表判为不合法，parseBackup在写入IndexedDB前重新校验所有历史稿件时抛出与截图完全相同的错误。整份存档没有写入，刷新自然读回上一次成功落盘的内容。

上一轮a01e188只解决未变动的历史/未来角色号码随单字段MVU回放被拒，未覆盖/custom整块快照遗漏新字段。新增回归修复前实际抛出上述同文案，调用链parseBackup→validateOutcome→applyMvu→validateTerminalCodeMap。

没有读取用户实际公网存档，不能认定这是其唯一触发条件，也不能保证已因刷新丢失的内存内容可以恢复。

## 修复

仅当操作对/custom执行整块replace/add/insert，结果未提供终端码字段，并且没有直接更新或移出终端码路径时，继承原状态已经存在的终端码表。按程序自有固定字段保护处理，不回退版本，不删除角色、号码、正文或历史回合，不重写原始历史补丁。

直接删除号码表/号码、提供空表删除原绑定、改动已有号码、绑定未知ID，以及整块/custom更新同时操作号码路径，继续执行原有严格校验。显式冲突不会被修复逻辑吞掉。
