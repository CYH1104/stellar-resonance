# 记忆 API 调用说明（仅记录现状）

本次未修改记忆系统。

1. **生成前检索**：没有已整理好的记忆时不调用向量接口；有可用记忆时，将当前行动、状态和近期事件构成查询，单独调用配置的向量 API。调用失败退回关键词检索。
2. **剧情生成**：正文调用剧情 API；已检索到的记忆作为上下文传给它。
3. **每轮保存**：正文和状态完成后，先在本地保存该轮事件记忆占位记录。界面的“已保存，等待累计轮数后整理”是待整理状态，并不代表已经调用记忆模型。
4. **累计整理**：未整理轮数达到设置的间隔（默认 10，范围 1～20）时，单独调用“累计记忆整理”配置的文本模型。一轮间隔调用单轮记忆接口，多轮间隔调用批量接口；批量一次请求返回多轮记录，而不是每轮调用一次。成功后分别写入每轮事件记录。
5. **建立索引**：整理完成的文字再交给向量 API，最多每批 16 条；成功的向量保存在本地。
6. **手动操作**：“补记”会主动调用记忆整理 API；“补齐索引”调用向量 API；记忆搜索在有可用记忆时也可能调用向量 API。

“累计记忆整理”与剧情是独立请求，但默认路由可跟随主 API，因此可能使用同一地址和同一模型。配置独立副 API 后，记忆整理请求使用该配置。向量 API 使用独立配置和 embeddings 接口，不能用普通聊天模型替代。

当前自动整理在正文保存后由同一生成任务接着等待，因而界面可能仍显示忙碌；这不表示记忆整理和正文是同一次 HTTP 请求。整理失败时正文仍保留。首次关系显示“首次建立 → 0”是程序计算的状态差异，不足以证明人物被模型登记为在场。
