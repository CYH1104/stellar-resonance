## 国王游戏最终规则（覆盖旧 Slack 方案中的系统拦截表述）

背叛是出卖用户秘密、协助陷害、为利益主动伤害用户；普通分歧、拒绝和正常社交不算。

当出现背叛命令，必须由 CHAR 以自己身份拒绝，并承担拒绝命令的正常游戏惩罚，例如罚酒或适合角色的罚茶。展示角色的语言、动作和承担惩罚的结果，不出现“系统拒绝生成/执行”。惩罚本身如果仍要求背叛，则角色拒绝该惩罚，改为正常惩罚。

国王不持有编号，其余成员获得一一对应的随机编号；出令前不展示他人的编号映射。用户被选中时停下等待输入，不代答。

## 数据与 API

- `Session.terminal` 为可选字段，旧存档无需迁移；终端跟随当前账号 IndexedDB 内的会话保存、导入和导出。没有额外全局 localStorage 通讯库，也没有跨账号玩家聊天。
- `personalTerminal.ts` 管理好友资格、会话/房间容量、随机抽签、编号、轮次状态、原子回应校验和备份校验。
- 终端通讯与游戏不修改正文、好感、剧情变量或主记忆。游戏记录独立保存。没有把终端聊天自动总结进主线记忆。
- `POST /api/personal-terminal` 使用现有会话认证、同源限制、接口白名单与已确认连接；Key 为临时请求参数，不存入终端存档。
- 任务为 group-plan / friend / invite / chat / schedule / command / evaluate / react；review 为服务端结果复核。结构校验禁止未知角色、玩家冒充、缺失目标、非法编号及异常课程时间。
- 角色反应成功后，再使用同一已配置模型进行一次语义复核；复核不通过/异常不返回可提交结果，当前轮保留供手动重试。用户自填命令额外进行语义判断。这里不是先前讨论的独立管理员监测 API。
- 继承提示词获取基础规则检查。语义限制依赖模型判断及复核，不能宣称绝对防绕过；正则只覆盖部分明显形式。主请求通常比普通聊天增加判断/复核调用，可能增加等待与用量。
- 请求有90秒总超时；切换存档/接口后旧结果不应用。聊天失败保留用户消息，可手动重试，不自动重复调用。
