# 终端提示收拢与备份传输

基于 main `e63cf14`。本次仅修改浏览器代码，9000 可热更新，不重启生成服务；8807、8088 不改。

## 终端提示

手机顶部只展示当前分支最近一轮/阶段的一个未完成提示；最近任务完成后不再展示以前失败轮次的卡片。按任务实际执行轮次排序，兼容终端先行的前一轮锚点和旧任务格式；不让旧轮重试、已经丢弃的轮次或其他回复分支覆盖当前提示。旧任务状态及消息不修改，完整备份继续保留这些记录。

## 备份传输

用户反馈 Gitee 已连接且可读列表，上传数秒后发生浏览器 fetch 失败。无令牌预检目前允许 GET/POST/PUT 及对应请求头，因此不能仅凭截图确认是跨域限制、平台请求体限制或网络拦截；没有读取客户令牌或真实仓库内容。

浏览器直连保持默认，失败时不会自动把数据和令牌发给本站。页面新增“备份传输方式”，用户可手动选择“服务器中转”，页面明确说明备份与令牌临时经过本站服务器。选择只存在于当前页面，不写入配置/备份；无新增持久化字段或文件格式。中转复用已存在且受登录与同源校验保护的 `/api/cloud-backup`，只允许 GitHub/Gitee 固定端点，保留平台 SHA 并发更新保护。原有中转请求上限 12 MiB 不变，超限有独立提示；直连不新增大小限制。

失败提示保留操作和具体步骤，区分直连失败、中转不可达、登录失效、请求过大、超时及平台拒绝。不会静默切换平台、自动重发写操作或把网络错误当上传成功。取消后忽略迟到的下载结果；网络中断不保证撤销已经提交的平台写入，需刷新列表核对。本次未改动平台适配器、服务端、备份收集和恢复逻辑。
