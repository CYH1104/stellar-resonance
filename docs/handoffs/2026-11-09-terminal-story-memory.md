# 9000 终端正文记忆与预设导入修正

基线：`901d6137af4b94626e6ae694bb9c099f4b4cb964`。本次仅发布 9000 前端；8807、8088 与线上后端进程保持原状。

## 已确认的问题与修复

- 自动通讯的历史正文原先每轮只发送前 2400 字符，本轮正文只发送前 16000 字符。改为在原预算内保留开头和结尾，并明确标记中间省略，避免漏掉结尾的新行动和约定。
- 自动通讯的记忆预算原先被最早的事实占满。现在按已确认剧情轮次从新到旧选取，独立于后台摘要的完成顺序；仍保留知情者标记，不把未知知情范围扩大为公开。
- 手动私聊／群聊仅靠检索命中，短句或检索异常会得到空记忆。现在在检索之外附带最近已完成、分支有效且符合全部收件人知情范围的事实；兼容旧结构化记忆里可唯一确定的本人行动及未履行约定。检索仍用于寻找远期相关信息，日志记录近期事实和检索结果的数量。
- 记忆检索阶段纳入取消与发送前检查：换档、改接口、停用手机或分支变化后，不再发送迟到的旧请求。既有模型响应写回检查保留。
- 修复已知失败：先终端后正文时，修改触发行动再生成会复用旧通讯事实。显式编辑过的行动以输入指纹区分任务，未编辑的旧存档继续沿用原任务 ID；相同行动的重试、刷新不重复生成。备份格式和任务字段不变。
- 导入预设按 `prompt_order` 排列实际条目，保持原开关、分组及未插入条目；明确排序允许 jailbreak 条目在历史之前，不再无条件移到末尾。
- 普通导入的兼容检查改为提醒，不自动关闭输出条目。界面确认页保持原有开关，用户仍可明确选择启停。旧版本明确关闭的条目和已手动排序的存量配置不擅自恢复／重排；要采用文件中的原顺序应重新导入原文件。

## 验证范围

- 合成请求捕获：短输入、检索为空及异常时，近期知情事实仍发送；其他人物私密事实、未知事实、未完成正文及废弃分支不发送。
- 慢检索期间换档：迟到请求不发出、任务释放。现有任务／API／保存失败／并发配置／备份测试一并执行。
- 已知失败转为正常测试，另验证修改行动后的任务 ID、事实、本地备份恢复和幂等重试。
- 三份用户预设分别验证导入后的排序和条目开关一致：万象合鸣 278 条、万事成真 325 条、Puppy 297 条；未执行文件内脚本。
- 独立 Edge 浏览器、合成模型响应、真实 IndexedDB：两种顺序分别推进四轮，验证消息实时显示及误归档恢复；实际下载完整文件、导入、云端格式采集与覆盖、覆盖前副本恢复，核对预设顺序／开关及终端记录一致，云端不含 API Key。
- 浏览器验证的云端上传／下载使用本机采集和覆盖入口，未真实写入 GitHub／Gitee。未使用真实计费模型或客户存档。

最终验证：前端 143 文件、808 项通过，无预期失败；后端 450 项通过、4 项跳过；类型检查和生产构建通过。线上资源核验记录在部署后写入 agent-hub；本机详细证据保留在当前工作区既有 `.integration/prompt-memory-*` 下。

## 仍有边界

- 近期正文事实必须已整理成分支有效的结构化记忆；尚未完成的后台摘要不作为可信记忆。无知情范围的整段正文不直接发给所有 NPC。
- 国王游戏的匿名出令、回应和房间互动继续使用原有房间专用上下文，本次未改它们的后端协议。
- 本次不是完整酒馆兼容：HTML 美化正则、完整脚本扩展、未知扩展宏（包括 `Supervisor_role`）、`roll` 宏、请求内变量的跨轮持久化及专属采样设置仍有未支持项。预设里的模拟手机不是学院的实际终端记录。
- 旧预设已丢弃的外部扩展或参数，不能从现有导入结果反向还原；需要保留原文件。未新增持久化字段、数据库或 localStorage 配置。
