# 新版架构：酒馆原生后端、服务器存储、学院前端

2026-10-30，依据用户最新要求。此决定取代旧迁移方案中“浏览器IndexedDB为权威、酒馆仅作执行投影”的目标。只用于新版独立分支，现有8807/9000不作试改。

**当前60db93f代码尚未完成此切换。本文是新的实施依据，不能将文档更新说成服务器存储已上线。**

## 核心规则

- 以原生SillyTavern为主要后端，尽可能直接使用原生加载、默认值、格式、宏、生成、采样、世界书、聊天、正则、向量和扩展能力。
- 新版服务器账号数据为唯一持久化权威。同账号换浏览器、换设备、重启后应能取得同一份已保存资料。
- 保留学院现有页面、CSS、布局和交互；主要替换数据来源、操作绑定和必要适配，不借迁移重做皮肤。
- 状态、小剧场、论坛和手机等学院功能作为明确扩展保留。兼容层负责扩展和旧资料转换，不再建设另一套较窄的酒馆引擎。
- 浏览器可有内存、可丢弃缓存和待迁移旧副本，但不能在服务器保存失败时静默回退成本地成功，也不保持两份业务权威双写。

## 数据映射

| 数据 | 首选原生保存方式 | 学院适配内容 |
|---|---|---|
| 正文/对话 | 原生chats接口、JSONL聊天文件 | 轮次与原生消息对应；保留输入、回复、时间。 |
| 多稿/分支 | 原生swipes、swipe_info、聊天分支及metadata | 旧Turn/Variant身份、选中稿及状态来源；额外字段使用有版本的扩展元数据，不丢旧稿。 |
| 聊天变量 | 原生聊天metadata及变量机制 | 学院MVU、好感、在场等扩展，防止跨存档串状态。 |
| 人设/头像 | 原生Persona、用户头像和设置 | 主人设引用、精神体、备注、备忘录和sourceSessionIds使用命名空间扩展。 |
| 角色 | 原生角色卡及关联配置 | 学院固定世界/多NPC映射；手机群聊不冒充原生多卡群聊。 |
| 预设 | 原生presets接口、对应API预设目录 | 保留原始JSON和未知扩展，沿用原生加载与字段语义。 |
| 世界书 | 原生worldinfo接口、worlds目录 | 统一原生书库与执行入口；特殊任务绑定/角色范围单独适配。 |
| 设置 | 原生settings接口、settings.json | 学院布局/小剧场等放extension_settings独立命名空间，保留其他插件设置。 |
| 手机/终端 | 对应聊天metadata的学院扩展，必要时账号目录内的扩展记录 | 全部私聊、群聊、联系人、申请、课程、房间、轮次、占卜、来源和知情范围。 |
| 记忆/检索 | 优先原生Memory/Vectors能力及持久化 | 学院事实、承诺、来源与知情范围；不能继续用文本专用桥冒充embeddings通道。 |
| 正则/助手/脚本 | 原生扩展及指定助手的设置和存储 | 实际操作与事件桥、前端管理入口；不是只存字段不执行。 |
| 图片/立绘/资源 | 原生账号资源目录及文件/头像接口 | 迁移旧Blob和URL；服务器保存资源与Git云备份的图片排除策略分别处理。 |
| 草稿 | 原生设置扩展或账号目录内扩展草稿记录 | 未应用草稿与已生效设置分离，不能被聊天自动保存顺带激活。 |
| 凭据 | 独立凭据机制，模型Key优先原生Secrets | 不混入预设、世界书、草稿和普通备份。 |
| 恢复副本 | 原生聊天/设置备份及学院扩展恢复信息 | 覆盖前形成完整一致副本，含人设、终端、资源引用和扩展数据。 |

已核对固定原生源码的src/endpoints/chats.js、settings.js、presets.js、worldinfo.js和users.js。具体接口/格式以固定版本真实行为为准，不另造同名接口冒充复用。

仅将旧浏览器workspace整包写入服务器JSON、继续使用旧引擎，不算完成本次目标。原生聊天/预设/世界书/设置应由原生接口和格式承接；学院独有字段才进入扩展。

## 页面和兼容要求

1. 学院前端保留现有桌面及移动CSS，显示组件通过适配后的视图模型工作。
2. 预设/世界书界面统一原生数据，借鉴旧页面清晰布局，条目折叠时可直接启停。
3. 助手扩展菜单必须连到真实操作、脚本和配置，不能只加魔法棒图标。
4. 以固定原生版本真实加载和编排行为为兼容标准，移除额外过窄规则，如学院写死的32000上限；资源限制与格式错误分开提示。
5. 账号、凭据和既有私有资料边界继续保留，不因换皮肤默认授权把完整提示词/Key下发玩家脚本。

## 旧资料迁移

1. 使用完整采集入口，包含所有稿件、人设库、主人设、备注/备忘录、草稿、全部终端记录、预设/世界书、设置和资源引用。原本地数据库原样保留。
2. 先形成可下载完整副本，转换为原生数据与学院扩展，试写后回读比对。所有持久化项校验通过才标记迁移成功。
3. 服务器已有数据时不在登录时自动覆盖。提供明确追加/替换语义和冲突处理，替换前保留恢复副本；更换ID要重绑全部关联。
4. 中断、写入失败或并发冲突保持明确未完成状态，不删除旧副本，不触发模型重算，不重复通讯/结算/向量任务。
5. 成功切换后服务器成为唯一权威，浏览器旧库只作为迁移来源/恢复副本，不继续普通双写。

## 实施及验收顺序

1. 固定原生用户目录与身份，验证实际文件保存、重启、换浏览器/设备和账号隔离。
2. 完成聊天、设置、预设、世界书、资源及学院扩展映射，再切前端全部持久化入口；不能仅改主Repository而漏掉独立人设库和localStorage配置。
3. 重接完整下载、云上传、导入、拉取覆盖及覆盖前恢复；凭据、运行日志和模型原始输出继续不进普通备份，URL保留。
4. 验证旧格式、全资料往返、磁盘/网络失败、跨页面/设备修改、迁移中断和恢复。
5. 对比学院桌面/移动CSS及原交互，做固定原生同文件/同参数/同消息行为对照。
6. 最后验收正式原生启动、真实供应商、Linux和容量，再处理独立部署。用户此前暂缓部署要求继续有效。
