# 撤回消息与正文补修对照折叠栏

本次基于共享 main `caf4d4c8cee642ecf3b4bf598f3daf572d87da77`，仅调整撤回和对照展示，不重写伙伴的状态、记忆或 API 调用规则。

## 撤回

- 原“从此幕重来”改名“撤回”，在用户消息、模型回复菜单均可使用，菜单本身的位置不变。
- 从模型回复撤回时，连同对应的上一条用户发言一起移除。撤回历史轮次时，仍按既有回退语义移除该轮及之后的剧情；确认弹窗明确说明影响范围。
- 用户发言放回输入框，不自动发送、不调用剧情接口。已有草稿时弹窗明确提示会替换；打开确认后若草稿、消息或会话发生变化，则拒绝旧确认，要求重新选择。
- 状态从剩余选中分支重放；对应记忆退出当前召回、任务标为 stale，论坛和互动按原分支清理。正在执行的旧记忆结果不能重新插入已撤回轮次，失败处理也不会覆盖 stale 标记。
- 输入草稿随账号隔离的工作区保存，刷新后重新进入会话可恢复。保存失败时恢复撤回前的对话和输入，不显示成功。
- “删除问答”仍为原来的删除操作，不恢复用户输入；“重演”仍为生成新稿，两者与撤回区分。

## 正文下方对照

- 从操作菜单移除的是 `StateRepairReport` 对照折叠栏，不是移动操作菜单。
- 对照在对应正文下方，默认折叠；“显示／隐藏变量变化”同时控制原变量差异栏和补修对照栏。
- 最新一次补修对照绑定在具体 variant，包含实际提交的字段前后值、在场及好感度对照、校验原因和失败信息。无变化时明确显示原值保持不变。
- 记录随备份和刷新保留，切换稿件时切换对应记录；新续写稿不会冒用旧稿记录，手动编辑相关文本后清除旧对照。显示字段最多 200 项，超出时标明；不限制实际状态保存。
- 对照是程序比较真实前后状态得到，不包含模型隐藏推理，也不会把被拒绝的命令冒充已应用变化。

## 参考角色卡

已读取用户提供 PNG 内的 `chara` 数据、世界书及变量更新条目。可借鉴之处是：初始化与更新分开、当前变量为基准、JSON Patch 仅变更满足条件的字段、数值增量不能在同一事件重复结算、只读字段保护、更新与渲染分离。该卡内同时存在旧式命令和 JSON Patch 规则，部分条目原本关闭，未将其直接执行或全部导入学院。

本次沿用学院既有 MVU、数值范围、作者资料保护及记忆处理；不照搬卡片的数值、剧情或输出思考要求。
