# v0.15.0 随机事件先选择、后掷骰和正文

日期：2026-10-16（Asia/Shanghai）。上一版见 QA-v0.14.0.md。

从每轮自动掷骰改为开启后新回合独立50%命中。crypto.getRandomValues配合拒绝采样避免取模偏差；类别另一次独立均匀抽取突发、奇遇、危机、修罗场、惊喜。未命中不调用事件API，直接正常剧情。命中后单独POST /api/random-event，沿现有本机会话、同源、URL登记和Key校验；发送玩家人设、本轮行动、最近六个完整回合、当前在场ID及服务端世界约束，要求只返回尚未发生的情境标题和悬念，不生成正文或MVU。响应严格校验、过滤显式思考、只返回候选。90秒超时、响应大小限制、最多2000输出Token；用户可停止。

Turn.randomEvent持久化none、preparing、failed、pending、accepted、declined、skipped。待选卡片有拒绝及Roll D100两个按钮；没有空白正文假装生成。拒绝不向主线传候选且无骰点；接受原子保存决定和唯一D100后发送主线。specialEvent与dice一起进入主线系统规则及上下文，限定落实同一候选和点数方向，旧diceEvent校验继续生效。重试、重演、续写、仅状态补修沿用决定、类别和骰点；候选失败可以同类重试或跳过，不重抽概率。刷新恢复等待阶段，不自动调用模型；旧无randomEvent的存档可恢复。未决定不许新增后续回合；备份拒绝等待阶段附带正文、后续回合或骰点。修改待定行动会重新准备同类候选。

随机事件API在模型设置独立选择主/副接口，默认主API；仅功能开启时列入必需接口。删除被选副API恢复主API。Key仍仅浏览器凭据库保存，不进入存档、备份、日志或私有世界文件。主线正文、MVU、各小剧场仍由剧情接口一次生成。

验证：110项Vitest、96项Node测试，共206项通过；类型检查与生产构建通过。新增概率边界、五类分布、拒绝采样、候选清理、备份阶段一致性、首次生成门控、接受及拒绝、未命中零候选请求、独立副API、失败重试及跳过、刷新恢复及连续点击不重掷、UI服务端渲染、候选HTTP真实路由与参数拒绝、主线事件/骰点约束。延续旧主线、续写、状态补修、API、隐私和论坛回归。未读取真实Key、未调用付费模型、未进行浏览器点击或视觉验收（此前浏览器访问限制仍遵守）。本轮仅更新本机，未上传GitHub。
