# 用户世界书与服务器内置世界书（v0.20.0）

预设和世界书各有独立顶部菜单页。世界书是设定资料，记忆是当前存档实际发生的事情，二者分别检索和注入。

## 用户使用

进入“世界书”，导入酒馆世界书 JSON，或新建世界书和条目。左边复选框决定该书是否用于当前存档；未打开存档时编辑的是新游戏默认绑定。新游戏复制默认绑定，之后各存档独立修改。导入的书自动绑定当前存档或新游戏默认配置，同名文件再次导入会成为另一份书，不覆盖原书。

条目支持折叠、编辑、启用／停用、删除。世界书支持复制、修改扫描设置、删除及导出酒馆 JSON。“测试触发”只在本机匹配关键词，不调用模型，也不检查或展示服务器内置资料。真实概率依据回合标识稳定抽取，测试与真实回合结果可能不同。

世界书库及存档绑定保存在同一 IndexedDB 快照，包含在“导出全部备份”中；追加恢复会重映射书的标识，避免与原书或原存档串绑。删除书解除所有存档绑定。导出单份世界书不包含剧情、记忆、Key 或服务器设定。

## 兼容范围

- 酒馆 `{entries:{uid:entry}}` JSON、`entries` 数组，以及 JSON 中独立或嵌入的 `character_book`。只提取世界书，不导入人物卡字段。
- 常驻／关键词、条目开关、主要／次要关键词与 AND ANY、AND ALL、NOT ANY、NOT ALL。
- 扫描深度（消息条数）、大小写、英文整词；中文词仍按包含匹配。支持逐条追加人设、角色描述、性格、角色深度提示、场景和作者备注扫描，含 camelCase 与嵌入卡 snake_case 开关。缺少的字段按空内容处理，不阻断普通关键词；当前页面只提供存档中已有的公开角色身份／能力和开场场景，不提供服务器私有角色卡全文，也不把隐藏内心当作扫描来源。
- 触发概率、顺序、递归扫描、不被递归激活、不触发后续递归、指定递归层开始。递归最多 20 层，条目单次最多插入一次。
- 位置 0（角色定义前）、1（角色定义后）、4（聊天指定深度），深度位置支持 system/user/assistant。user、char、persona、charIfNotGroup 宏只展开一次；char 是稳定世界卡叙述者，不是当前在场 NPC。
- 未识别字段以 JSON 数据保留用于导出，不作为代码运行。导出统一为酒馆对象 entries 格式。

**2026-11-10：移除“存在兼容提示就整条跳过”的限制。** 导入确认页保留原开关，不因额外扫描或扩展选项默认关闭条目。常驻、主要／次要关键词、四种选择逻辑、扫描深度、概率、递归、包含组与角色作用范围仍决定是否触发；没有主要词的普通条目不改为常驻。已经被旧版关闭的条目需手动开启或重新导入原文件，不自动改变用户现有开关。

正则关键词按酒馆的正则优先方式匹配，前端正式生成与“测试触发”均在独立 Worker 中执行，支持取消及超时终止，超时会停止当前生成并保留输入，不在主线程重跑复杂表达式。支持生成类型过滤、角色名／标签过滤及忽略单书预算（本轮总预算仍保留）。

粘滞／冷却／延迟、世界书向量触发、自动化脚本和高级宏尚未完整接入。这些选项保留并提示，但不再连带禁用整条设定；基础常驻／关键词触发仍生效。作者注、示例对话或 Outlet 的专用插入位置尚无对应容器，命中内容暂放到角色定义后，提示说明这一差异，导出仍保留原位置。不能把这称为完整酒馆扩展兼容；不执行用户附带脚本。世界书向量触发与剧情记忆向量检索是独立能力。

预算使用字符数，不冒充模型精确 token 计数。默认每书 30000 字符，本轮用户世界书总计最多 100000 字符；优先保留顺序值较大的命中条目，超预算信息保留在世界书页。单文件上限 5MB、每书 10000 条、库最多 40 份且规范化数据共 12MB，全部备份仍有原来的 20MB 上限。

## 服务器部署

现有 `server/private/extracted-pro.json` 中的角色和世界定义仍留在服务器，原有行为保留。可额外把内置酒馆世界书 JSON 放入：

```text
server/private/worldbooks/
  internal-world.json
  internal-characters.json
```

目录可不存在。服务器启动时读取目录内 JSON，并用相同触发引擎处理；新增或修改文件后重启。非法文件使启动明确失败，不自动换成空设定。此目录已被 `server/private/` 的 Git 忽略规则覆盖；应用只提供 dist 中限定路径，不提供该目录或世界书查看／下载 API。bootstrap 不返回书名、条目或触发结果。

用户世界书在浏览器里按本轮输入和已选完整剧情分支匹配，只发送实际触发的内容、位置、角色和顺序；整份书及附加元数据不发送。内置书在服务器对现有剧情请求历史匹配（当前最多最近 12 轮），与用户书分别递归，用户条目不能利用递归过程探查私有条目。记忆、论坛及小剧场不自动当作已经发生的主线扫描来源。

触发内容在预设组装后按位置插入，不改写预设条目开关及原有提示词角色；服务器另加边界提示，要求核心设定优先、保持玩家身份及输出协议。模型需要读取的内置资料仍会发给用户选定的模型供应商；“不返回网页原文”不等于能够保证模型永不在对话中透露设定。不要在世界书中放 Key 等真实秘密。

触发与注入不新增模型调用，正文、小剧场和 MVU 仍使用原剧情调用；每轮记忆 API 和可选向量 API 沿用既有流程。

参考：[SillyTavern World Info 官方文档](https://docs.sillytavern.app/usage/core-concepts/worldinfo/) 与 [官方字段及导入映射](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/world-info.js)。实现为独立的数据导入与触发模块，没有下载执行酒馆或用户插件。
