# 动态 NPC 与关系状态

NPC 不再限定为服务器内置角色表。用户人设中的亲属、启用世界书中的人物、作者后续增加的人物以及正文中新出现的人物，都可由当前状态模型在同轮注册，无需增加一次模型调用。

新增角色必须提供稳定且唯一的 `id` 与非空 `name`。格式合法的其余角色字段按现有规则保存，好感度范围仍为 -100～200。未在现场的哥哥、朋友等应保存 `present:false` 和已有关系，不因提及而自动标为在场。不从人设文本硬编码猜测姓名或关系，由模型依据当前输入、人设和已启用世界书输出。

状态 JSON 示例：

```json
{"presentCharacterIds":[],"characters":[{"id":"npc-brother","name":"林川","present":false,"relationship":"哥哥","affinity":35}],"event":"谈及哥哥"}
```

MVU 新增示例：

```json
[{"op":"add","path":"/characters/npc-brother","value":{"id":"npc-brother","name":"林川","present":false,"relationship":"哥哥","affinity":35}}]
```

后续使用相同 ID 更新具体字段；不得删除已有角色或借新增覆盖玩家和已有角色的身份字段。既有模型请求、存档、分支重演、导出恢复均携带动态人物。关系页也展示已注册的动态人物和已明确关系的非在场人物。

关闭状态功能时不注册模型新返回的角色。新规则在学院档案的内部 AI 提示词中可查看、编辑；旧自定义提示词中的“只允许已知 ID”规则应更新。此功能保证合法返回能被接收，不保证模型每次都能主动识别人设中的所有人物。
