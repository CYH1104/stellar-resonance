# 9000 浏览器直传与人设页面资源恢复

本次以 `1b006dc6c54c0b402553665f3b7ec36d50642033` 为基准，仅发布 9000 前端。8807、8088、后端进程和数据结构不改。

## 浏览器直传

按用户要求撤回上一版的服务器中转选项。连接、列表、上传、下载全部由用户浏览器直接访问所选 Gitee/GitHub 平台，仓库令牌和备份内容不发送到本站备份接口。

写请求的响应可能被网络或跨域限制拦截，但平台实际已经保存。此时只进行一次有时限的读回校验：完整备份解析后与待上传内容相同，才能确认成功。旧文件、不同内容、读取失败或取消均不得误报成功；不自动重复写入。已确认上传成功后，列表刷新失败单独提示，不改称上传失败。

沿用完整备份采集、导入及覆盖前恢复入口，无新增持久化字段。人设、备注、备忘录、草稿、预设/世界书和终端记录继续包含在备份中；云端排除本地图片、API/仓库密钥、运行日志及原始模型输出。

## 人设页面

客户反馈为点击人设档案后空白、全局样式失效。截图能看到已有姓名和字段，不能据此认定档案已删除。正常隔离环境未复现客户故障，客户浏览器中的具体资源失败原因仍未取证。

为已知故障路径补保护：人设异步模块加载失败显示明确提示，重载前先保存现有工作区；保存失败则保留页面。基础样式未加载、被禁用或丢失时，使用构建时从现有样式入口生成的内联副本。进入人设档案时保留同一套样式，无重绘设计、无轮询、无人设清理或重建。

## 验证及边界

- 前端全套 147 文件、836 项测试通过；最终构建包含类型检查。浏览器直传测试覆盖失败、超时信号、取消和迟到结果，不借用模型 API。
- 独立 Edge、真实生产页面组合：阻断主 CSS，阻断人设异步 JS/CSS，再恢复资源并重载；进入档案后移除外部主样式，布局仍保留。测试前后 IndexedDB 人设姓名及备忘录一致。
- 独立 Edge、真实跨源模拟平台：7 存档、约 7.35 MB 完整备份。实际阻断写响应的 CORS，验证“已保存”与“未保存”两种结果；无重复写、无本站中转请求；实际 IndexedDB 拉取覆盖、覆盖前副本及撤销恢复通过。
- 数据往返仍使用原有兼容性测试；本次未改变备份文件格式或存储提交协议。没有重新对所有原生多文件写入阶段逐一注入故障，也不能据此声称所有历史存储风险消失。
- 模拟跨源平台不是客户真实 Gitee/GitHub 仓库。未读取客户密钥、未写客户仓库，真实平台上传仍需用户复核；不承诺浏览器能绕过平台自身 CORS 或网络限制。
- 发布采用保留旧哈希资源、原子切换入口的前端热更新，验证公开资源内容和原有服务未重启。

后续若客户仍出现样式失效，应采集那次页面的控制台与失败资源信息继续定位；保留浏览器数据，不清空存储，不用恢复旧备份覆盖现有人设。
