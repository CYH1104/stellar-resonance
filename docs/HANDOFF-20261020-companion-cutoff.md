# 论坛截断、群聊保留与正文基础排版

## 本次反馈确认

用户提供的原始返回包含一段额外的 Markdown 论坛、完整 status、四个独立 choices 数组，以及中途截断的 forum JSON。没有 theater slot=2。因此这次空群聊不能解释为已返回的群聊被界面丢弃。

## 修改

- 正文支持文本形式的粗体、斜体、代码、标题和分隔线，不执行输入 HTML 或脚本。
- 明确带论坛标题及帖子 ID、作者、内容标签的预设论坛附录折叠保留；不会转换成权威论坛数据，也不会匹配普通叙事提到论坛的段落。
- 内置输出模板要求每个模块只返回一次；小剧场在论坛之前完成，避免重复 Markdown 论坛占用后续输出预算。此调整不能保证上游永不截断。
- 四个相邻 JSON 字符串数组可恢复为一组快捷回复，必须完整匹配整段输入。
- theater 外层 slot 可补足 JSON 中缺省的 slot；显式 JSON slot 不覆盖。
- 空群聊不覆盖已有有效群聊。缺失模块不会凭空生成，也不自动追加模型调用。
- 论坛、小剧场标签未闭合时显示明确诊断，其他有效状态继续保存。
- NPC 精神体 OS 缺省显示“对方精神体未出现”；玩家缺省提示保留。

## 验证

服务端 288 项、前端 360 项测试通过；类型检查和生产构建通过。包含用户返回结构的定向复现、空群聊保留、标签 slot 恢复、相邻 choices 数组、截断论坛及文本安全渲染测试。本次未进行线上真实模型调用，推送代码也不等于服务器已经更新。

## 线上复测

更新服务器并刷新页面后，开启论坛和群聊生成一轮：检查状态卡、四个快捷回复、群聊手机和论坛；查看原始返回应只有一份论坛。人为减少输出预算造成截断时，应保留正文及已完成模块，显示缺失诊断，不用空群聊覆盖旧记录。历史失败回合不会自动重生成，使用该回复的补全功能处理。
