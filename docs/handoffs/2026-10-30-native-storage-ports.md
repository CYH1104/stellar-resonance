# 原前端接原生后端：存储适配检查点

本轮基线 `23affdbb`，只改独立原生迁移分支。**完整前端仍未接通全部运行时，未部署。8088 仍是上一阶段的精简入口；8807、9000 未改动。** 不要把本轮存储验证说成前端整体已交付。

## 本轮实际实现

- `src/native/api.ts` 使用原生会话/CSRF 和已有接口，明确处理会话过期、聊天完整性失败、非预期响应，不回退旧服务。文件与头像分别通过原生 files/upload 和 avatars/upload。
- `academyMessages.ts` 仅做学院视图到原生消息数组的映射，不写 JSONL。开场、输入、全部稿件映射为原生消息及 swipes；Session/Turn/Variant 的其他业务数据进入版本化扩展元数据，包含手机、私聊、游戏房间、记忆、变量及分支关联。保留其他原生扩展字段，拒绝未知学院标记/版本、重复关联和不完整多稿。
- `repository.ts` 调用原生 characters/create、chats/get/save/delete。偏好、输入草稿、编辑器草稿、文件索引及恢复标记使用原生 settings；覆盖前副本使用原生文件上传接口。终端独立保存从当前快照合并，不用调用者旧快照覆盖其他数据。接受现有 Vue JSON 视图。
- `presets.ts` 用原生预设/世界书文件接口；扩展设置只保存 ID、名称、任务与存档绑定，不复制一套预设文件存储。修正重命名留下旧文件和同名文件误覆盖；恢复 Default 调用原生预设恢复接口。取消学院额外的 19 份预设、500000 字符及 32000 输出限制，仍保留凭据和格式检查。
- `personas.ts` 把人设姓名/描述写入原生 personas/persona_descriptions，学院表格、独立档案名、备注、备忘录、sourceSessionIds、头像外观及未完成草稿保留在扩展元数据。原图经原生文件接口保存，原生头像经原生图像转换接口保存。人设独立 revision 避免输入草稿变化错误阻挡恢复。
- 图片以内容哈希核对；读不到图片时档案文字仍可查看，严格备份报错而非静默缺图；普通保存不能顺便清除未读到的原图。最终 settings 保存失败时不覆盖原头像文件。草稿保存不覆盖原生界面刚修改的人设正文。
- `credentials.ts` 把 Key 写入原生 Secrets，普通设置只存 secret ID。每次请求使用独立 secret_id，不通过切换全局活动 Key 区分正文/终端；保存完成恢复原活动密钥，不删除其他原生密钥。接口设置导出不能把 ID 冒充原始 Key；受保护且 RAM 不可用时要求重新输入。

## 数据与备份边界

本轮没有新增用户逻辑数据种类：原有 BackupArchive/Session 字段映射到原生物理存储。恢复指针、密钥 ID、人设 revision、原生头像名和原图文件引用属于内部关联；导出必须先还原为原有领域对象/Blob，再走现有完整备份采集与云端图片/密钥排除规则。不能直接上传 settings.json 或原生文件路径充当完整备份。

**现有完整备份入口尚待与具体运行时一起接通，不能声称下载/上传/导入/拉取/恢复这五条真实前端路径已验收。** 当前原生实测验证的是存储接口往返及恢复文件，现有备份回归验证的是格式和策略，两者尚未合成完整用户链路。
