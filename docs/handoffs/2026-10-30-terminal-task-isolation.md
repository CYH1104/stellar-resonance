# 终端任务隔离与记忆回滚修复

基线 `f180474bc1e1f0a569c29b28abbb75028da8142e`，独立分支 `rebuild/sillytavern-native`。用户要求继续下一步；先读频道总方案及接力棒，选择方案明确要求优先修复的四项终端旧缺陷。main 和 8807／9000 不更新。

## 修复内容

1. **保存失败误伤独立记忆**：终端任务不再用旧整份 memories 数组回滚。比较同步应用前后实际改动，只撤销仍等于该次任务写入值的记录；同期新增、编辑、删除的独立记忆保留，对同一条派生记忆的后续编辑也不覆盖。终端自身结果仍按既有事务失败流程撤销并保留可重试状态。
2. **行动变更复用旧事实**：新自动任务身份带 `auto2:` 命名空间。终端先行绑定当前输入指纹及前置分支；正文先行及社交核验绑定当前完成稿分支。修改输入不会复用旧缓存，旧记录仍保留。可验证的旧阶段继续复用；无法证明来源的旧事实不当作当前阶段的已提交事实。
3. **多稿／续写取错事实**：按所选稿件和有效锚点查找，优先选择该稿的正文后阶段，避免以前的共享先行缓存盖过当前稿件。复制完成稿续写时，使用已有 job 字段保存 `continuation-context` 投影；续写中断、再续写和刷新后仍能取得同一来源，不额外调用终端。原稿及原结果不改写。旧阶段与上下文投影不被误重试到新行动／稿件。
4. **换接口未中止在途任务**：终端接口、模型、地址或 Key 改变时立即 abort，并继续保留 epoch／签名二次校验。行动、前置分支、所选稿件、顺序或存档变化也会取消绑定请求；即使上游忽略中止，结果仍不能写到新分支。中止本机请求不等于承诺提供商立即停止计费。

额外补齐终端先行改为正文先行后再重说／续写的优先级场景。没有改变终端 API 路由规则、已有好友／群权限、游戏玩法或正文默认调用次数。
