# 2026-10-24 SSE响应识别和异常诊断修复

基于main a01e188，工作区干净，fetch核对无伙伴新提交。用户授权修复“服务器应返回SSE流式响应”。本轮只改前端HTTP网关，不修改服务器模型协议或自动重试次数。

## 复现及修复

新增generation-response.test.ts，修复前5类检查失败：响应头MIME大小写不规范、实际SSE被标为text/plain/octet-stream、HTTP200包装的JSON错误、HTML/空响应、API重定向。旧代码把多数情况统一抛为“服务器应返回SSE流式响应”，无法区分原因。

新增generationResponse模块：
- MIME按大小写不敏感的标准类型识别，忽略参数。
- MIME标注错误时检查实际SSE帧前缀，复用原应用事件解析与后续状态校验，不把任意HTML、OpenAI原始JSON或非流式结果当成功。
- HTTP200但含白名单后台code的JSON错误映射为明确原因；HTML、空响应、其他内容分别报告安全HTTP状态及MIME类别。不展示原始响应、页面正文、重定向地址或查询参数。
- 非SSE诊断读取上限8192字符；取消未消费流、释放reader，不自动重发或切换接口。
- API POST使用redirect:manual，不把带Key/正文的请求自动跟随到其他路由；浏览器opaqueredirect及HTTP3xx明确提示检查会话和API路由。
- 缓存中已有完整帧时先处理，不额外等待网络；保留UTF-8解码器处理跨块中文，兼容CRLF、BOM和结束处缺少空行的最后事件。

## 限制与后续

原用户那次失败的实际响应未被捕获，因此不能认定就是其中某一种原因。误标响应头但内容确实为有效应用SSE时，本修复可直接兼容；如果实际返回的是登录页、代理错误页或错误JSON，应根据新诊断修正相应会话/后台路由/上游问题，不能承诺前端能让错误页面变为正常剧情。
